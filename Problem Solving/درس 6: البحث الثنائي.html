البحث الثنائي (Binary Search)

ستتعلم كيف تجد ما تبحث عنه بين مليون عنصر في 20 خطوة فقط، وكيف تكتب الحدود بدون أخطاء، وكيف تبحث عن الجواب نفسه حتى لو لم تكن هناك قائمة.

الدرس 6 من 8 المستوى: متوسط اللغة: Python وقت القراءة: 40 دقيقة

📚 محتوى الدرس

مقدمة تشبيه من الحياة المصطلحات الأساسية المفاهيم الأساسية كيف يعمل من الداخل أمثلة الكود الأخطاء الشائعة أفضل الممارسات الأداء والموازنات مشروع تطبيقي اختبر نفسك تمارين الخلاصة الخطوة التالية

مقدمة

📝 تذكير: في الدرس 2 رأيت أن القسمة على 2 في كل خطوة تعطي O(log n). وفي الدرس 3 استخدمت ترتيب القائمة لتحذف عنصرًا في كل خطوة بالمؤشرين. البحث الثنائي يذهب أبعد من ذلك: هو يحذف نصف العناصر في كل خطوة.

الفكرة تبدو سهلة: انظر إلى العنصر في المنتصف، ثم احذف النصف الذي لا يمكن أن يكون فيه الجواب. لكن البحث الثنائي مشهور بأخطاء الحدود: حلقة لا تنتهي، أو جواب يزيد أو ينقص بواحد. لذلك سنتعلم قالبًا واحدًا مع ثابت واضح، ونستخدمه في كل المسائل.

الاستخدام الأقوى للبحث الثنائي ليس البحث في قائمة. هو البحث في مجال الجواب (Binary Search on the Answer). مثلًا: "ما أقل حد يومي للتحويل يكفي لصرف كل الرواتب خلال 3 أيام؟". هنا لا توجد قائمة مرتبة، لكن الطريقة تعمل.

في هذا الدرس ستتعلم البحث الكلاسيكي، والحد الأدنى والحد الأعلى، ووحدة bisect، والبحث في مجال الجواب. وفي النهاية ستبني حاسبة لأقل سعة يومية لصرف الرواتب.

تشبيه من الحياة

🔢 لعبة التخمين: صديقك اختار رقمًا بين 1 و 100، وبعد كل تخمين يقول لك "أكبر" أو "أصغر". إذا خمنت 1، ثم 2، ثم 3، فقد تحتاج 100 محاولة. أما إذا خمنت 50 دائمًا، ثم 25 أو 75، وهكذا، فتكفيك 7 محاولات على الأكثر، لأن كل إجابة تحذف نصف الأرقام الباقية.

المفاهيم الأساسية

لماذا هو سريع جدًا؟

بعد k خطوة يبقى n / 2ᵏ عنصر. نتوقف عندما يبقى عنصر واحد:

$$\frac{n}{2^k} = 1 \;\Rightarrow\; k = \log_2 n \qquad n = 10^6 \Rightarrow k \approx 20,\quad n = 10^9 \Rightarrow k \approx 30$$

الفكرة الأهم: كل بحث ثنائي هو "أول True"

لا تفكر في البحث الثنائي على أنه "ابحث عن رقم". فكر فيه هكذا: عندك شرط قيمه False في البداية ثم True حتى النهاية، وأنت تبحث عن الحد الفاصل.

مثال: القائمة [2, 5, 8, 12, 16, 23, 38] والشرط nums[i] >= 12:

5F
8F
12T ← أول True
16T
23T
38T

إذا فهمت هذا، فكل المسائل تصبح سؤالًا واحدًا: ما الشرط الرتيب في هذه المسألة؟

القالب الواحد

lo, hi = first_candidate, last_candidate_plus_one   # search space [lo, hi)
while lo < hi:
    mid = (lo + hi) // 2
    if condition(mid):      # True: answer is mid or to its left
        hi = mid
    else:                   # False: answer is strictly to the right
        lo = mid + 1
return lo                   # first index where condition is True (or hi if none)
💡 الثابت (Invariant): كل ما قبل lo قيمته False، وكل ما من hi وبعده قيمته True. كل دورة تصغّر المجال، لأن mid < hi دائمًا، و mid + 1 > lo دائمًا. لذلك تنتهي الحلقة، وعندما يلتقي lo و hi نكون عند الحد الفاصل.

ثلاثة استخدامات

1. البحث عن قيمة

هل الرقم موجود في قائمة مرتبة؟ وأين؟

2. الحدود

أول موقع ≥ x، وآخر موقع ≤ x، وعدد مرات ظهور x، وأين تضيف x مع الحفاظ على الترتيب.

3. البحث في مجال الجواب

أصغر سعة، أو أقل سرعة، أو أقل وقت يحقق شرطًا. القيم هي المجال، وليست قائمة.

البحث في مجال الجواب خطوة بخطوة

عندك دفعات رواتب يجب صرفها بالترتيب: [500, 300, 700, 200, 400, 600]. ما أقل حد يومي يكفي لصرفها كلها خلال 3 أيام؟ لا توجد قائمة نبحث فيها، لكن هناك شرط رتيب: إذا كان حدٌّ ما يكفي، فكل حد أكبر منه يكفي أيضًا.

  • أقل قيمة ممكنة: 700، أي أكبر دفعة، لأن الدفعة لا تُقسم.
  • أكبر قيمة نحتاجها: 2700، أي المجموع كله، فيكفي يوم واحد.

الخطوة 1: جرّب 1700

lo = 700, hi = 2700 → mid = 1700
day 1: 500+300+700+200 = 1700 | day 2: 400+600 = 1000 → 2 days ≤ 3 ✅

1700 يكفي، إذن الجواب 1700 أو أقل. hi = 1700.

الخطوة 2: جرّب 1200

lo = 700, hi = 1700 → mid = 1200
day 1: 800 | day 2: 700+200 = 900 | day 3: 400+600 = 1000 → 3 days ≤ 3 ✅

1200 يكفي أيضًا. hi = 1200.

الخطوة 3: جرّب 950

lo = 700, hi = 1200 → mid = 950
day 1: 800 | day 2: 900 | day 3: 400 | day 4: 600 → 4 days > 3 ❌

950 لا يكفي، إذن الجواب أكبر من 950. lo = 951.

الخطوة 4: بعد 11 فحصًا ✅

... 1075 ✅, 1013 ✅, 982 ❌, 998 ❌, 1006 ✅, 1002 ✅, 1000 ✅, 999 ❌ → lo = hi = 1000

الجواب 1000. جربنا 11 قيمة فقط من أصل 2001 قيمة ممكنة، لأن log₂ 2001 ≈ 11. وكل فحص يمرّ على الدفعات مرة واحدة، فالتعقيد O(n log S)، حيث S مجموع الدفعات.

أمثلة الكود

مثال 1: البحث الكلاسيكي (مجال مغلق)

def binary_search(nums: list[int], target: int) -> int:
    """nums sorted ascending. Returns an index of target, or -1.
    Time: O(log n), Space: O(1)."""
    lo, hi = 0, len(nums) - 1          # closed interval [lo, hi]
    while lo <= hi:                     # interval not empty
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1                 # target is to the right
        else:
            hi = mid - 1                 # target is to the left
    return -1


nums = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
print(binary_search(nums, 23))
print(binary_search(nums, 7))
print(binary_search([], 7))
5 -1 -1

الشرح سطرًا بسطر

  1. hi = len(nums) - 1: المجال مغلق، أي hi موقع صالح.
  2. while lo <= hi: عندما يكون lo == hi يبقى عنصر واحد، ويجب أن نفحصه.
  3. mid + 1 و mid - 1: فحصنا mid، فنحذفه من المجال. هذا يضمن أن الحلقة تنتهي.
  4. هذا الشكل مناسب عندما تريد "هل القيمة موجودة؟" فقط. لكنه لا يعطيك أول ظهور عندما تتكرر القيمة. لذلك نحتاج القالب التالي.

مثال 2: الحد الأدنى ووحدة bisect

from bisect import bisect_left, bisect_right


def lower_bound(nums: list[int], target: int) -> int:
    """First index i with nums[i] >= target (len(nums) if none)."""
    lo, hi = 0, len(nums)              # half-open [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] >= target:        # condition: F F F T T T
            hi = mid
        else:
            lo = mid + 1
    return lo


nums = [1, 2, 2, 2, 5, 7]
print(lower_bound(nums, 2), bisect_left(nums, 2))
print(lower_bound(nums, 3), bisect_left(nums, 3))
print(lower_bound(nums, 9))
print("count of 2:", bisect_right(nums, 2) - bisect_left(nums, 2))
1 1 4 4 6 count of 2: 3

الشرح سطرًا بسطر

  1. hi = len(nums): المجال نصف مفتوح، فقد يكون الجواب "بعد آخر عنصر". هذا يحدث عندما تكون كل القيم أصغر من الهدف، كما مع 9.
  2. hi = mid وليس mid - 1: الموقع mid يحقق الشرط، فقد يكون هو الجواب. لا نحذفه.
  3. lower_bound(nums, 3) يرجع 4: هذا هو المكان الذي تضيف فيه 3 مع الحفاظ على الترتيب، رغم أن 3 غير موجود.
  4. bisect_left هو نفس الدالة، لكنه مكتوب بلغة C، فهو أسرع. استخدمه في الكود الحقيقي.
  5. bisect_right يرجع أول موقع قيمته أكبر تمامًا من الهدف. الفرق بين الاثنين هو عدد مرات ظهور القيمة، ويُحسب بتعقيد O(log n).

مثال 3: البحث في مجال الجواب (الجذر التربيعي الصحيح)

from typing import Callable


def first_true(lo: int, hi: int, pred: Callable[[int], bool]) -> int:
    """Smallest x in [lo, hi] with pred(x) True.
    pred must be monotonic (F..F T..T) and pred(hi) must be True."""
    while lo < hi:
        mid = (lo + hi) // 2
        if pred(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo


def isqrt(n: int) -> int:
    """Largest x with x * x <= n, without floats."""
    # first x whose square is too big, minus one
    return first_true(0, n + 1, lambda x: x * x > n) - 1


print(isqrt(0), isqrt(15), isqrt(16), isqrt(10**18))
0 3 4 1000000000

الشرح سطرًا بسطر

  1. first_true: نفس القالب، لكنه يعمل على أي شرط وليس على قائمة. هذه الدالة وحدها تحل أغلب مسائل "مجال الجواب".
  2. الشرط: x * x > n رتيب. إذا كان مربع x أكبر من n، فمربع أي رقم أكبر من x أكبر أيضًا.
  3. المجال: n + 1 يحقق الشرط دائمًا، فالشرط pred(hi) مضمون.
  4. نحسب "أول قيمة كبيرة جدًا" ثم نطرح 1. هذه طريقة آمنة لتحويل "آخر True" إلى "أول True"، وتجنّب الحلقة التي لا تنتهي (انظر الخطأ 1).
  5. مع 10**18 نحتاج حوالي 60 دورة فقط. ولا نستخدم float، فلا توجد أخطاء تقريب. Python لديه هذه الدالة جاهزة باسم math.isqrt.

الأخطاء الشائعة

خطأ 1: حلقة لا تنتهي مع lo = mid

المطلوب: آخر موقع قيمته ≤ الهدف.

❌ الطريقة الخاطئة

def last_leq(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] <= target:
            lo = mid          # mid may equal lo
        else:
            hi = mid - 1
    return lo

# last_leq([1, 3], 5)  -> never ends!

✅ الطريقة الصحيحة

from bisect import bisect_right

def last_leq(nums: list[int], target: int) -> int:
    # first index > target, minus one (-1 means none)
    return bisect_right(nums, target) - 1

print(last_leq([1, 3], 5))  # 1
print(last_leq([1, 3], 0))  # -1
⚠️ لماذا الأولى خاطئة؟ مع lo = 0 و hi = 1، يكون mid = 0. الشرط صحيح، فيصبح lo = mid = 0، ولا يتغير شيء، فتتكرر نفس الدورة إلى الأبد. القسمة // تقرّب للأسفل، فقد يساوي mid قيمة lo. الحل الأفضل: حوّل "آخر True" إلى "أول True للشرط المعاكس، ناقص واحد". وإذا كان لا بد من lo = mid، فاستخدم mid = (lo + hi + 1) // 2.

خطأ 2: البحث الثنائي على بيانات غير مرتبة

❌ الطريقة الخاطئة

nums = [8, 2, 23, 5]          # NOT sorted
print(binary_search(nums, 8))  # -1  wrong! 8 is at index 0

✅ الطريقة الصحيحة

nums = [8, 2, 23, 5]
print(nums.index(8))           # one search: O(n) -> 0

sorted_nums = sorted(nums)     # many searches: sort once
print(bisect_left(sorted_nums, 8))  # 2 (index in the sorted copy)
⚠️ لماذا الأولى خاطئة؟ عند mid = 1 القيمة 2 أصغر من 8، فيحذف البحث كل ما قبلها ومنه العدد 8 نفسه. حذف النصف صحيح فقط إذا كان الشرط رتيبًا. لاحظ أيضًا أن الترتيب يغيّر المواقع، كما في الخطأ 2 من الدرس 1. وإذا احتجت بحثًا كثيرًا بدون ترتيب، فالـ set من الدرس 4 أسرع.

أخطاء أخرى متكررة

  • عدم التحقق من النتيجة: bisect_left يرجع موقعًا دائمًا. تحقق من i < len(nums) and nums[i] == target قبل أن تقول "وجدته".
  • خلط نوعي المجال: hi = len(nums) - 1 مع while lo < hi مع hi = mid - 1. اختر نوعًا واحدًا والتزم به. نصيحتي: المجال نصف المفتوح مع القالب الواحد.
  • تجاوز الحد في لغات أخرى: في Java و C++ قد يتجاوز lo + hi أكبر عدد صحيح. اكتب lo + (hi - lo) // 2. أما في Python فالأعداد الصحيحة لا حد لها.
  • مجال جواب خاطئ: إذا لم يكن hi يحقق الشرط مؤكدًا، فقد يرجع القالب hi وهو ليس جوابًا. اختر hi بحيث تعرف أنه يكفي.
  • البحث على float بشرط lo < hi: قد لا يلتقيان أبدًا بسبب التقريب. كرر عددًا ثابتًا من المرات، مثل for _ in range(100)، أو حوّل إلى أعداد صحيحة (القروش).
  • التكلفة المخفية في insort: إيجاد المكان O(log n)، لكن الإضافة في وسط القائمة تحرك العناصر، فتكلّف O(n).

أفضل الممارسات

  • اكتب الشرط بالكلمات أولًا، مثل "أول حد يومي يكفي لإنهاء الصرف خلال D أيام". ثم تأكد أنه F F F T T T.
  • استخدم قالبًا واحدًا دائمًا (first_true). كل مسألة "آخر قيمة" حوّلها إلى "أول قيمة" للشرط المعاكس ناقص واحد.
  • استخدم bisect مع القوائم المرتبة. هو مختبر وسريع. ومنذ Python 3.10 يقبل المعامل key=.
  • حدّد المجال بعناية: lo أصغر قيمة ممكنة للجواب، و hi قيمة تعرف أنها تكفي.
  • اختبر الحالات الطرفية: قائمة فارغة، وعنصر واحد، والهدف أصغر من الكل، والهدف أكبر من الكل، وكل العناصر متساوية.
  • اختبر بالضغط: قارن بالبحث الخطي على قوائم عشوائية صغيرة، كما تعلمت في الدرس 1. أخطاء البحث الثنائي تظهر غالبًا مع قوائم فيها عنصر أو عنصران.
💡 إشارات في نص المسألة: "مرتبة" مع قيود كبيرة مثل n ≤ 10⁹ تشير إلى البحث الثنائي. وعبارات مثل "أقل قيمة ممكنة لـ..." و "أكبر قيمة ممكنة لـ..." و "أقل سعة" و "أقل سرعة" و "خلال D أيام" تشير غالبًا إلى البحث في مجال الجواب.

الأداء والموازنات

البحث الخطي مقابل البحث الثنائي

عدد المقارنات في أسوأ حالة. الرسم بمقياس لوغاريتمي. مع مليار عنصر: مليار مقارنة مقابل 30.

هل يستحق الترتيب التكلفة؟

الترتيب يكلّف O(n log n) مرة واحدة. إذا كنت ستبحث k مرة:

$$\underbrace{k \cdot n}_{\text{linear}} \quad \text{vs} \quad \underbrace{n \log n + k \log n}_{\text{sort + binary search}}$$

الترتيب يستحق عندما تكون k أكبر من log n تقريبًا. مع مليون عنصر، تكفي حوالي 20 عملية بحث.

مشروع تطبيقي صغير: أقل حد يومي لصرف الرواتب

القصة: شركة تريد صرف رواتب موظفيها خلال D أيام على الأكثر. الدفعات في طابور ويجب صرفها بالترتيب، ولا تُقسم الدفعة الواحدة. البنك يحدد حدًّا يوميًا لمجموع التحويلات، وكلما زاد الحد زادت الرسوم. المطلوب: أقل حد يومي يكفي.

طبّق الخطوات الست

  1. الفهم: المدخلات قائمة مبالغ (أعداد صحيحة)، و max_days. المخرجات أصغر حد يومي.
  2. الحالات الطرفية: يوم واحد (الجواب هو المجموع)، وأيام بعدد الدفعات أو أكثر (الجواب هو أكبر دفعة)، وقائمة فارغة.
  3. الحل البدائي: جرّب كل حد من أكبر دفعة إلى المجموع، بتعقيد O(n · S). هذا بطيء جدًا مع مبالغ كبيرة.
  4. التحسين: الشرط "هل هذا الحد يكفي؟" رتيب. لذلك نستخدم البحث الثنائي في مجال الجواب، مع دالة فحص جشعة (greedy): املأ كل يوم قدر الإمكان.
  5. الكود: بالأسفل.
  6. الاختبار: 3 أيام، ويوم واحد، و 6 أيام.
def days_needed(payouts: list[int], capacity: int) -> int:
    """Greedy: fill each day as much as possible. Time: O(n)."""
    days, today = 1, 0
    for amount in payouts:
        if today + amount > capacity:   # doesn't fit -> start a new day
            days += 1
            today = 0
        today += amount
    return days


def min_daily_capacity(payouts: list[int], max_days: int) -> int:
    """Smallest daily limit that finishes within max_days.
    Time: O(n log S), S = sum(payouts). Space: O(1)."""
    if not payouts:
        return 0
    lo, hi = max(payouts), sum(payouts)   # hi always works (one day)
    while lo < hi:
        mid = (lo + hi) // 2
        if days_needed(payouts, mid) <= max_days:   # feasible -> try smaller
            hi = mid
        else:
            lo = mid + 1
    return lo


def schedule(payouts: list[int], capacity: int) -> list[list[int]]:
    plan: list[list[int]] = [[]]
    today = 0
    for amount in payouts:
        if today + amount > capacity:
            plan.append([])
            today = 0
        plan[-1].append(amount)
        today += amount
    return plan


payouts = [500, 300, 700, 200, 400, 600]   # in EGP, must be paid in order

cap = min_daily_capacity(payouts, 3)
print(cap)
print(schedule(payouts, cap))
print(min_daily_capacity(payouts, 1))
print(min_daily_capacity(payouts, 6))
1000 [[500, 300], [700, 200], [400, 600]] 2700 700

الشرح

  1. lo = max(payouts): أي حد أقل من أكبر دفعة لا يمكن أن يصرفها، لأن الدفعة لا تُقسم. هذا يضمن أيضًا أن days_needed صحيحة.
  2. hi = sum(payouts): يكفي دائمًا، لأن كل الدفعات تُصرف في يوم واحد.
  3. لماذا الشرط رتيب؟ زيادة الحد لا تزيد عدد الأيام أبدًا. إذن إذا كفى حدٌّ ما، كفى كل حد أكبر منه.
  4. days_needed جشعة: تملأ اليوم الحالي قدر الإمكان. هذا صحيح هنا، لأن تأجيل دفعة إلى الغد لا يقلل عدد الأيام أبدًا.
  5. مع 6 أيام يكون الجواب 700، أي أكبر دفعة، وتكفي 5 أيام فعلًا.
  6. التعقيد O(n log S). حتى لو كان المجموع مليار جنيه، يكفي حوالي 30 فحصًا.
💡 نمط عام: نفس الكود يحل مسائل كثيرة: أقل سعة لشاحنة تنقل الطرود خلال D أيام، وتقسيم قائمة إلى k أجزاء متصلة بأقل أكبر مجموع، وأقل سرعة لإنهاء عمل في وقت محدد. غيّر دالة الفحص فقط، واترك البحث الثنائي كما هو.

اختبر نفسك

1. كم مقارنة يحتاج البحث الثنائي في أسوأ حالة مع مليون عنصر؟
2. ما الشرط الوحيد الضروري للبحث الثنائي؟
3. nums = [1, 2, 2, 2, 5]. ما قيمة bisect_left(nums, 2) و bisect_right(nums, 2)؟
4. لماذا قد لا تنتهي حلقة فيها lo = mid و mid = (lo + hi) // 2؟
5. في مشروع الرواتب، لماذا يمكن استخدام البحث الثنائي رغم أنه لا توجد قائمة مرتبة نبحث فيها؟

تمارين

قبل كل تمرين، اكتب الشرط الرتيب بالكلمات، وحدد lo و hi.

تمرين 1 (سهل): موقع الإضافة

اكتب دالة search_insert(nums: list[int], target: int) -> int. ترجع موقع target إذا وُجد في قائمة مرتبة بدون تكرار، أو الموقع الذي يجب أن يُضاف فيه. لا تستخدم bisect.

💡 تلميح

الموقع في الحالتين هو أول موقع قيمته ≥ target. ابدأ بالمجال [0, len(nums)).

✅ الحل 
def search_insert(nums: list[int], target: int) -> int:
    # Time: O(log n), Space: O(1)
    lo, hi = 0, len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] >= target:
            hi = mid
        else:
            lo = mid + 1
    return lo


print(search_insert([1, 3, 5, 6], 5))
print(search_insert([1, 3, 5, 6], 2))
print(search_insert([1, 3, 5, 6], 7))
2 1 4

هذا هو lower_bound نفسه. لاحظ أن hi = len(nums) هو الذي يسمح بالجواب 4، أي بعد آخر عنصر.

تمرين 2 (متوسط): أول وآخر ظهور

اكتب دالة search_range(nums: list[int], target: int) -> tuple[int, int]. ترجع أول وآخر موقع للقيمة في قائمة مرتبة، أو (-1, -1). المطلوب O(log n) حتى لو تكررت القيمة مليون مرة.

💡 تلميح

أول ظهور هو bisect_left. وآخر ظهور هو bisect_right - 1. لا تنسَ أن تتحقق أن القيمة موجودة.

✅ الحل 
from bisect import bisect_left, bisect_right


def search_range(nums: list[int], target: int) -> tuple[int, int]:
    # Time: O(log n), Space: O(1)
    left = bisect_left(nums, target)
    if left == len(nums) or nums[left] != target:
        return (-1, -1)
    return (left, bisect_right(nums, target) - 1)


print(search_range([5, 7, 7, 8, 8, 10], 8))
print(search_range([5, 7, 7, 8, 8, 10], 6))
print(search_range([], 0))
(3, 4) (-1, -1) (-1, -1)

لو وجدت القيمة ثم مشيت يمينًا ويسارًا لتجد أول وآخر ظهور، يصبح التعقيد O(n) عندما تتكرر القيمة كثيرًا. بحثان ثنائيان يبقيان O(log n).

تمرين 3 (متوسط): أقل سرعة للأكل (Koko Eating Bananas)

عندك أكوام موز piles، وتأكل k موزة في الساعة من كوم واحد. إذا كان الكوم أقل من k، تنهيه وتنتظر حتى نهاية الساعة. اكتب دالة min_eating_speed(piles: list[int], h: int) -> int ترجع أقل سرعة k تنهي بها كل الأكوام خلال h ساعة.

💡 تلميح

الوقت اللازم لكوم p هو ceil(p / k)، ويُكتب بأعداد صحيحة (p + k - 1) // k. المجال من 1 إلى max(piles). الشرط: "هل مجموع الساعات ≤ h؟"، وهو رتيب.

✅ الحل 
def min_eating_speed(piles: list[int], h: int) -> int:
    # Time: O(n log M), M = max(piles). Assumes len(piles) <= h.
    def hours(k: int) -> int:
        return sum((p + k - 1) // k for p in piles)   # integer ceil

    lo, hi = 1, max(piles)        # speed max(piles) finishes in len(piles) hours
    while lo < hi:
        mid = (lo + hi) // 2
        if hours(mid) <= h:
            hi = mid
        else:
            lo = mid + 1
    return lo


print(min_eating_speed([3, 6, 7, 11], 8))
print(min_eating_speed([30, 11, 23, 4, 20], 5))
print(min_eating_speed([30, 11, 23, 4, 20], 6))
4 30 23

نفس شكل مشروع الرواتب بالضبط، والذي تغيّر هو دالة الفحص فقط. استخدمنا (p + k - 1) // k بدل math.ceil(p / k) لنتجنب float.

تمرين 4 (صعب): البحث في قائمة مرتبة ومُدارة

قائمة مرتبة تم تدويرها عند نقطة لا تعرفها، مثل [4, 5, 6, 7, 0, 1, 2]. القيم غير مكررة. اكتب دالة search_rotated(nums: list[int], target: int) -> int ترجع موقع القيمة أو -1، بتعقيد O(log n).

💡 تلميح

القائمة كلها ليست مرتبة، لكن عند أي mid يكون أحد النصفين على الأقل مرتبًا. إذا كان nums[lo] <= nums[mid] فالنصف الأيسر مرتب. تحقق هل الهدف داخل النصف المرتب: إذا كان داخله فابحث فيه، وإلا فابحث في النصف الآخر.

✅ الحل 
def search_rotated(nums: list[int], target: int) -> int:
    # Time: O(log n), Space: O(1)
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[lo] <= nums[mid]:                 # left half is sorted
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                                      # right half is sorted
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1


print(search_rotated([4, 5, 6, 7, 0, 1, 2], 0))
print(search_rotated([4, 5, 6, 7, 0, 1, 2], 3))
print(search_rotated([1], 1))
4 -1 0

هنا لا يوجد شرط رتيب على القائمة كلها، لكن في كل خطوة نستطيع أن نحدد بأمان أي نصف نحذفه. وهذا هو جوهر البحث الثنائي: معلومة واحدة عند mid تكفي لحذف النصف. استخدمنا <= في nums[lo] <= nums[mid] لحالة lo == mid.

الخلاصة

  • البحث الثنائي يحذف نصف المجال في كل خطوة، فالتعقيد O(log n): مليون عنصر يحتاج 20 خطوة.
  • الشرط الوحيد هو الرتابة: F F F T T T. القائمة المرتبة حالة خاصة.
  • فكّر دائمًا في "أول True"، واستخدم قالبًا واحدًا: while lo < hi، و hi = mid، و lo = mid + 1.
  • الثابت: ما قبل lo قيمته False، وما من hi وبعده قيمته True.
  • bisect_left أول موقع ≥ x، و bisect_right أول موقع > x، والفرق بينهما عدد مرات الظهور.
  • حوّل "آخر True" إلى "أول True للشرط المعاكس ناقص 1"، حتى تتجنب الحلقة التي لا تنتهي.
  • البحث في مجال الجواب: حدّد lo و hi، واكتب دالة فحص، وابحث عن أصغر قيمة تكفي. التعقيد O(n log Range).
  • تحقق دائمًا من النتيجة، واختبر القوائم الفارغة والصغيرة جدًا.
