مقدمة

📝 مستوى الدرس: اخترت لك مستوى متوسطًا، ولغة Python، ومسألة واحدة نتابعها في كل الدرس. هذا الدرس هو الأول في سلسلة من 8 دروس.

حل المشكلات (Problem Solving) مهارة، وليس حفظًا للحلول. أغلب المبرمجين يقرؤون المسألة ثم يبدؤون الكتابة فورًا. بعد ذلك يضيعون الوقت في إصلاح أخطاء كان من السهل تجنبها.

لماذا يهمك هذا؟ لأنك ستواجه مسائل جديدة كل يوم في العمل وفي المقابلات التقنية. الحلول المحفوظة لا تساعدك أمام مسألة لم ترها من قبل. أما الطريقة المنظمة فتساعدك في كل مسألة.

في هذا الدرس سنحل مسألة واحدة اسمها Two Sum بطريقة منظمة. ستبدأ بحل بطيء وصحيح، ثم تحسّنه، ثم تختبره. بعد ذلك ستطبّق نفس الخطوات على مسألة من عالم المدفوعات.

تشبيه من الحياة

🩺 فكّر في الطبيب الجيد. هو لا يكتب الدواء في أول دقيقة. أولًا يسمع منك، ثم يسألك أسئلة، ثم يفحصك. بعدها يختار العلاج، ثم يطلب منك العودة ليرى هل نجح العلاج.

حل المشكلات البرمجية يشبه ذلك تمامًا: افهم ← اسأل ← جرّب حلًا بسيطًا ← حسّن ← نفّذ ← تحقّق. المبرمج الذي يكتب الكود مباشرة يشبه طبيبًا يكتب الدواء قبل أن يسمع الشكوى.

الخطوات الست

1. افهم المسألة

أعد كتابة المسألة بكلماتك. حدد المدخلات والمخرجات والقيود.

2. أمثلة وحالات طرفية

اكتب أمثلة صغيرة بيدك، ومعها حالات غريبة.

3. حل بدائي

ابدأ بأي حل صحيح، حتى لو كان بطيئًا.

6. اختبر وراجع

الخطوة 1: افهم المسألة

لماذا تبدأ بالفهم؟ لأن حل مسألة خاطئة بإتقان ما زال حلًا خاطئًا. اسأل نفسك هذه الأسئلة قبل أن تكتب أي كود:

  • هل القائمة مرتبة (sorted)؟ في مسألتنا: لا.
  • هل يمكن أن تكون الأرقام سالبة أو مكررة؟ نعم.
  • هل يمكن استخدام نفس العنصر مرتين؟ لا.
  • ماذا نرجع إذا كان هناك أكثر من جواب؟ أي جواب صحيح.
  • ما حجم القائمة؟ لنقل حتى 100,000 عنصر.

الخطوة 2: أمثلة وحالات طرفية

المدخلاتالمخرجاتلماذا هذا المثال؟

[5, 5], 10(0, 1)رقم مكرر.

الخطوة 3: الحل البدائي

جرّب كل زوج ممكن. هذا الحل سهل، وغالبًا يكون صحيحًا. وفائدته الكبرى أنه يصبح مرجعًا (reference) تختبر به الحل السريع لاحقًا.

الخطوة 4: التحسين بطريقة BUD

ابحث في الحل البدائي عن ثلاثة أشياء:

  • Bottleneck (عنق الزجاجة): ما الجزء الأبطأ؟ عندنا هو الحلقة الداخلية التي تبحث عن الرقم المكمل.
  • Unnecessary work (عمل غير ضروري): هل نحسب شيئًا لا نحتاجه؟
  • Duplicated work (عمل مكرر): هل نبحث في نفس الأرقام مرة بعد مرة؟ نعم.

الفكرة الأساسية: لكل رقم x نحتاج الرقم target - x. لذلك السؤال الحقيقي هو: هل رأيت هذا الرقم من قبل؟ وأسرع طريقة للإجابة عن سؤال "هل رأيته؟" هي القاموس (dict)، لأن البحث فيه يأخذ وقتًا ثابتًا تقريبًا.

seen = {3: 0, 8: 1, 4: 2} → return (2, 3)
📝 لماذا البحث في القاموس سريع؟ القاموس يحوّل المفتاح إلى رقم باستخدام دالة hash. هذا الرقم يحدد مكان المفتاح في الذاكرة مباشرة. لذلك لا يمرّ القاموس على كل العناصر، ويأخذ البحث في المتوسط وقتًا ثابتًا O(1).

أمثلة الكود

مثال 1: الحل البدائي O(n²)

def two_sum_brute(nums: list[int], target: int) -> tuple[int, int] | None:
    """Try every pair (i, j) with i < j."""
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):  # start after i: never reuse the same element
            if nums[i] + nums[j] == target:
                return (i, j)
    return None


print(two_sum_brute([3, 8, 4, 6, 1], 10))
print(two_sum_brute([5], 10))
(2, 3) None

الشرح سطرًا بسطر

  1. -> tuple[int, int] | None: الدالة ترجع زوج مواقع، أو None إذا لم تجد جوابًا.
  2. for i in range(n): نختار الرقم الأول.
  3. range(i + 1, n): نختار الرقم الثاني بعد الأول دائمًا. هكذا لا نستخدم نفس العنصر مرتين، ولا نكرر نفس الزوج.
  4. إذا كان المجموع يساوي target، نرجع الموقعين فورًا.
  5. return None: جربنا كل الأزواج ولم نجد جوابًا.

عدد الأزواج التي نجربها في أسوأ حالة:

$$\binom{n}{2} = \frac{n(n-1)}{2} \approx \frac{n^2}{2}$$

إذا كان n = 100,000، فهذا يعني حوالي 5 مليارات عملية. هذا بطيء جدًا في Python.

مثال 2: الحل المحسّن باستخدام dict بتعقيد O(n)

def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    """One pass: for each number, ask 'have I seen its complement?'"""
    seen: dict[int, int] = {}  # value -> index
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:           # check BEFORE storing num
            return (seen[need], i)
        seen[num] = i
    return None


print(two_sum([3, 8, 4, 6, 1], 10))
print(two_sum([5, 5], 10))
print(two_sum([5], 10))
print(two_sum([], 0))
(2, 3) (0, 1) None None

الشرح سطرًا بسطر

  1. seen: dict[int, int] = {}: قاموس يحفظ كل رقم رأيناه (المفتاح) وموقعه (القيمة).
  2. enumerate(nums): يعطينا الموقع والقيمة معًا.
  3. need = target - num: الرقم الذي يكمل الرقم الحالي.
  4. if need in seen: نبحث في القاموس بوقت ثابت تقريبًا. هذا السطر حلّ محل الحلقة الداخلية كلها.
  5. seen[num] = i: نضيف الرقم الحالي بعد البحث. لو أضفناه قبل البحث، يمكن أن يطابق الرقم نفسه.
💡 الموازنة: كسبنا وقتًا (من O(n²) إلى O(n))، لكن دفعنا ذاكرة إضافية O(n) للقاموس. هذه الموازنة بين الوقت والذاكرة (Time-Space Trade-off) تتكرر كثيرًا.

مثال 3: اختبار الضغط (Stress Testing) كما يفعل المحترفون

كيف تتأكد أن الحل السريع صحيح؟ قارنه بالحل البدائي على مئات المدخلات العشوائية الصغيرة. الحل البدائي بسيط، لذلك نثق به كمرجع.

import random


def two_sum_brute(nums: list[int], target: int) -> tuple[int, int] | None:
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return (i, j)
    return None


def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    seen: dict[int, int] = {}
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:
            return (seen[need], i)
        seen[num] = i
    return None


def is_valid(nums: list[int], target: int, answer: tuple[int, int]) -> bool:
    """A valid answer: two different positions whose values sum to target."""
    i, j = answer
    return i < j and nums[i] + nums[j] == target


def stress_test(rounds: int = 500) -> None:
    random.seed(42)  # same random inputs every run
    for _ in range(rounds):
        n = random.randint(0, 8)  # small inputs, includes the empty list
        nums = [random.randint(-5, 5) for _ in range(n)]
        target = random.randint(-10, 10)

        slow = two_sum_brute(nums, target)
        fast = two_sum(nums, target)

        # Both must agree on whether an answer exists
        if (slow is None) != (fast is None):
            print("Mismatch:", nums, target, slow, fast)
            return
        # The fast answer may differ from slow, but it must be valid
        if fast is not None and not is_valid(nums, target, fast):
            print("Invalid answer:", nums, target, fast)
            return
    print(f"All {rounds} tests passed")


stress_test()
All 500 tests passed

الشرح سطرًا بسطر

  1. random.seed(42): نثبّت العشوائية. هكذا تحصل على نفس المدخلات في كل تشغيل، وتستطيع إعادة أي خطأ.
  2. random.randint(0, 8): نستخدم قوائم صغيرة. القوائم الصغيرة تكشف الحالات الطرفية، ومنها القائمة الفارغة.
  3. randint(-5, 5): مجال ضيق يعني أرقامًا مكررة كثيرة وأرقامًا سالبة. هذا يكشف الأخطاء بسرعة.
  4. ملاحظة مهمة: لا نقارن slow == fast. الحلّان قد يرجعان زوجين مختلفين، وكلاهما صحيح. لذلك نتحقق من شيئين: هل يتفقان على وجود جواب؟ وهل جواب الحل السريع صحيح؟
  5. إذا ظهر خطأ، نطبع المدخلات التي سببته. بعدها تتتبعها بيدك.

الأخطاء الشائعة

خطأ 1: استخدام نفس العنصر مرتين

❌ الطريقة الخاطئة

def two_sum(nums: list[int], target: int):
    seen: dict[int, int] = {}
    for i, num in enumerate(nums):
        seen[num] = i          # stored first!
        need = target - num
        if need in seen:
            return (seen[need], i)
    return None

print(two_sum([5], 10))  # (0, 0)  wrong!

✅ الطريقة الصحيحة

def two_sum(nums: list[int], target: int):
    seen: dict[int, int] = {}
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:       # check first
            return (seen[need], i)
        seen[num] = i          # then store
    return None

print(two_sum([5], 10))  # None
⚠️ لماذا الأولى خاطئة؟ عندما نضيف 5 قبل البحث، يجد الكود 5 في القاموس، ويرجع (0, 0). هذا يعني أننا جمعنا العنصر مع نفسه. ترتيب سطرين فقط غيّر صحة الحل.

خطأ 2: الترتيب الذي يضيّع المواقع الأصلية

❌ الطريقة الخاطئة

def two_sum(nums: list[int], target: int):
    nums.sort()   # changes the input AND loses indices
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return (left, right)  # indices of the SORTED list
        if total < target:
            left += 1
        else:
            right -= 1
    return None

✅ الطريقة الصحيحة

def two_sum(nums: list[int], target: int):
    # keep (value, original_index) pairs
    pairs = sorted((v, i) for i, v in enumerate(nums))
    left, right = 0, len(pairs) - 1
    while left < right:
        total = pairs[left][0] + pairs[right][0]
        if total == target:
            i, j = pairs[left][1], pairs[right][1]
            return (min(i, j), max(i, j))
        if total < target:
            left += 1
        else:
            right -= 1
    return None
⚠️ لماذا الأولى خاطئة؟ المسألة تطلب مواقع القائمة الأصلية. بعد الترتيب، تتغير المواقع. والأسوأ أن nums.sort() يغيّر قائمة المستخدم نفسها. هذا خطأ في الخطوة 1 (الفهم)، وليس في الكود.

أخطاء أخرى متكررة

  • نسيان الحالات الطرفية: قائمة فارغة، عنصر واحد، كل العناصر متساوية.
  • التحسين قبل الصحة: حل سريع وخاطئ لا قيمة له. اكتب حلًا صحيحًا أولًا.
  • تجاهل القيود: إذا كان n ≤ 20، فالحل البدائي قد يكون كافيًا تمامًا.
  • الكتابة دون تتبّع: تتبّع الكود بيدك على مثال صغير قبل التشغيل.

أفضل الممارسات

  • اكتب المسألة بكلماتك في تعليق قبل الكود. إذا لم تستطع، فأنت لم تفهمها بعد.
  • اقرأ القيود أولًا. هي تخبرك بالتعقيد المطلوب (انظر الجدول في القسم التالي).
  • قل الحل البدائي بصوت مرتفع في المقابلة، حتى لو لم تكتبه. هذا يُظهر أنك تفهم المسألة.
  • اسأل: ما المعلومة التي أحسبها مرة بعد مرة؟ احفظها في dict أو set أو مصفوفة.
  • استخدم أسماء واضحة مثل need و seen، وليس x و d.
  • احتفظ بالحل البدائي لاختبار الضغط.
  • إذا علقت لأكثر من 10 دقائق، جرّب مثالًا أصغر، أو حلّ نسخة أبسط من المسألة.
💡 نصيحة: بعد كل مسألة، اكتب سطرًا واحدًا: "ما الفكرة التي فتحت الحل؟". بعد 50 مسألة ستملك دفترًا بالأنماط، وهذا أقوى من حفظ الحلول.

📝 متى لا تحتاج التحسين؟ إذا كانت المدخلات صغيرة دائمًا، فالحل البسيط أفضل لأنه أسهل في القراءة والصيانة. التحسين له تكلفة: كود أطول واحتمال أكبر للأخطاء.

مشروع تطبيقي صغير: مطابقة المدفوعات مع فاتورة

القصة: عميل دفع فاتورة على دفعتين. عندك قائمة معاملات (transactions)، ولكل معاملة رقم ومبلغ. ابحث عن معاملتين مجموعهما يساوي مبلغ الفاتورة بالضبط.

طبّق الخطوات الست

  1. الفهم: المدخلات قائمة (id, amount) ومبلغ الفاتورة. المخرجات رقما المعاملتين، أو None.
  2. الحالات الطرفية: مبالغ صفرية أو سالبة (مثل المبالغ المستردة refunds)، ومبالغ مكررة، وكسور عشرية.
  3. الحل البدائي: جرّب كل زوج. هذا بطيء مع آلاف المعاملات.
  4. التحسين: هي نفس مسألة Two Sum. نستخدم dict.
  5. الكود: نخزّن المبالغ بالقروش كأعداد صحيحة (int). لماذا؟ لأن 0.1 + 0.2 في Python لا يساوي 0.3 بالضبط.
  6. الاختبار: مثال فيه جواب، ومثال ليس فيه جواب.
Payment = tuple[str, int]  # (transaction_id, amount_in_cents)


def match_payments(payments: list[Payment], invoice_cents: int) -> tuple[str, str] | None:
    """Find two payments whose amounts sum exactly to the invoice."""
    seen: dict[int, str] = {}  # amount -> first transaction id with that amount
    for tx_id, amount in payments:
        if amount <= 0:
            continue  # skip refunds and invalid amounts
        need = invoice_cents - amount
        if need in seen:
            return (seen[need], tx_id)
        seen.setdefault(amount, tx_id)  # keep the earliest transaction
    return None


payments: list[Payment] = [
    ("TX1", 15000),   # 150.00
    ("TX2", 25050),   # 250.50
    ("TX3", 9950),    # 99.50
    ("TX4", 40000),   # 400.00
    ("TX5", -5000),   # refund, ignored
]

print(match_payments(payments, 35000))  # 350.00
print(match_payments(payments, 100))    # 1.00
print(0.1 + 0.2 == 0.3)                 # why we use cents
('TX2', 'TX3') None False

الشرح

  1. Payment = tuple[str, int]: اسم مختصر للنوع يجعل الكود أوضح.
  2. if amount <= 0: continue: قرار جاء من الخطوة 2. المبالغ المستردة لا تُحسب دفعة.
  3. seen.setdefault(amount, tx_id): إذا تكرر نفس المبلغ، نحتفظ بأول معاملة فقط.
  4. السطر الأخير يوضح لماذا لا نستخدم float مع المال.
💡 لاحظ: المسألة الحقيقية بدت جديدة، لكنها Two Sum في ثوب مختلف. هذه هي قيمة التفكير بالأنماط.

تمارين

طبّق الخطوات الست في كل تمرين. اكتب الأمثلة والحالات الطرفية قبل الكود.

تمرين 1 (سهل): هل يوجد تكرار؟

اكتب دالة has_duplicate(nums: list[int]) -> bool ترجع True إذا ظهر أي رقم أكثر من مرة.

💡 تلميح

الحل البدائي يقارن كل زوج بتعقيد O(n²). أي هيكل بيانات يجيب عن سؤال "هل رأيته من قبل؟" بسرعة؟

✅ الحل 
def has_duplicate(nums: list[int]) -> bool:
    seen: set[int] = set()
    for num in nums:
        if num in seen:
            return True   # stop early
        seen.add(num)
    return False


print(has_duplicate([1, 2, 3, 1]))
print(has_duplicate([1, 2, 3]))
print(has_duplicate([]))
True False False

نستخدم set لأننا نحتاج القيم فقط، لا المواقع. الوقت O(n) والذاكرة O(n). يوجد حل أقصر هو len(set(nums)) != len(nums)، لكنه لا يتوقف مبكرًا عند أول تكرار.

تمرين 2 (متوسط): أول حرف غير مكرر

اكتب دالة first_unique(text: str) -> int ترجع موقع أول حرف لا يتكرر في النص، أو -1 إذا لم يوجد.

💡 تلميح

استخدم مرورين على النص. في المرور الأول، احسب عدد ظهور كل حرف.

✅ الحل 
from collections import Counter


def first_unique(text: str) -> int:
    counts = Counter(text)            # pass 1: count each char
    for i, ch in enumerate(text):     # pass 2: find first with count 1
        if counts[ch] == 1:
            return i
    return -1


print(first_unique("paymob"))
print(first_unique("aabbcd"))
print(first_unique("aabb"))
0 4 -1

مروران على النص يعني O(n)، وهذا أفضل بكثير من O(n²). هذا نمط مهم: احسب المعلومة مرة واحدة، ثم استخدمها.

تمرين 3 (متوسط): الكلمات المتجانسة (Anagrams)

اكتب دالة is_anagram(a: str, b: str) -> bool. ترجع True إذا كانت الكلمتان تحتويان نفس الحروف بنفس العدد، مثل "listen" و "silent".

💡 تلميح

هناك حلّان: الترتيب بتعقيد O(n log n)، أو العدّ بتعقيد O(n). ابدأ بالتحقق من الطول.

✅ الحل 
from collections import Counter


def is_anagram(a: str, b: str) -> bool:
    if len(a) != len(b):   # quick exit
        return False
    return Counter(a) == Counter(b)


print(is_anagram("listen", "silent"))
print(is_anagram("rat", "car"))
True False

فحص الطول أولًا يوفّر وقتًا في حالات كثيرة. Counter هو dict يعدّ ظهور كل عنصر.

تمرين 4 (صعب): عدد القوائم الجزئية التي مجموعها k

اكتب دالة count_subarrays(nums: list[int], k: int) -> int. ترجع عدد القوائم الجزئية المتصلة (subarrays) التي مجموعها يساوي k. الأرقام قد تكون سالبة.

💡 تلميح

الحل البدائي يجرب كل بداية وكل نهاية. للتحسين، استخدم المجموع التراكمي (Prefix Sum). مجموع الجزء من i إلى j يساوي prefix[j] - prefix[i]. الآن السؤال هو: كم مرة رأيت prefix - k من قبل؟ أليس هذا مثل Two Sum؟

✅ الحل 
def count_subarrays(nums: list[int], k: int) -> int:
    count = 0
    prefix = 0
    seen: dict[int, int] = {0: 1}   # prefix sum -> how many times seen
    for num in nums:
        prefix += num
        count += seen.get(prefix - k, 0)
        seen[prefix] = seen.get(prefix, 0) + 1
    return count


print(count_subarrays([1, 1, 1], 2))
print(count_subarrays([1, 2, 3], 3))
print(count_subarrays([1, -1, 0], 0))
2 2 3

{0: 1} يمثل "مجموعًا فارغًا" قبل البداية، حتى نعدّ القوائم الجزئية التي تبدأ من الموقع 0. لا يمكن استخدام Sliding Window هنا بسبب الأرقام السالبة. لاحظ أن هذه المسألة هي Two Sum على المجاميع التراكمية. الوقت O(n).

الخلاصة

  • حل المشكلات مهارة لها خطوات واضحة، وليس حفظًا للحلول.
  • الخطوات الست: افهم، أمثلة، حل بدائي، حسّن، اكتب الكود، اختبر.
  • القيود تخبرك بالتعقيد المطلوب قبل أن تبدأ.
  • الحل البدائي الصحيح أهم من حل سريع خاطئ، وهو مرجعك في الاختبار.
  • استخدم BUD للتحسين: عنق الزجاجة، والعمل غير الضروري، والعمل المكرر.
  • سؤال "هل رأيت هذا من قبل؟" يعني غالبًا dict أو set.
  • أغلب التحسينات تبادل ذاكرة بوقت.
  • ترتيب سطرين قد يغيّر صحة الحل، لذلك تتبّع الكود بيدك.
  • اختبار الضغط يكشف أخطاء لا تكشفها أمثلتك اليدوية.
  • مسائل كثيرة تبدو جديدة، لكنها نمط معروف في ثوب مختلف.
