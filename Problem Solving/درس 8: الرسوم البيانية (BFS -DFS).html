مقدمة

📝 تذكير: في الدرس 2 تعلمت أن deque هو الطابور الصحيح. وفي الدرس 4 استخدمت dict و set للحفظ والبحث السريع. وفي الدرس 5 تعلمت العودية والتراجع. هذا الدرس يجمع الثلاثة: الطابور هو أساس BFS، والعودية أو المكدس أساس DFS، والـ set يحفظ ما زرناه.

الرسم البياني (Graph) هو طريقة لتمثيل أشياء وعلاقات بينها. الحسابات والتحويلات بينها، والخدمات والاعتماديات بينها، والمدن والطرق بينها، وخانات الخريطة وجيرانها. كلها رسوم بيانية.

لماذا يهمك هذا؟ لأن مسائل كثيرة لا تبدو مسائل رسوم بيانية في البداية. "هل هذه الحسابات مرتبطة ببعضها؟" و "بأي ترتيب نشغّل الخدمات؟" و "هل توجد حلقة تحويلات تعود إلى نفس الحساب؟". كل هذه أسئلة عن رسم بياني.

في هذا الدرس ستتعلم طرق التمثيل، والبحث بالعرض (BFS)، والبحث بالعمق (DFS)، واكتشاف الحلقات، والترتيب الطوبولوجي، وخوارزمية Dijkstra. وفي النهاية ستبني نظامًا يكشف شبكات الاحتيال من الأجهزة وأرقام الهواتف المشتركة.

تشبيه من الحياة

💧 البحث بالعرض (BFS): ارمِ حجرًا في بحيرة. الموجة تصل أولًا إلى كل النقاط على بعد متر واحد، ثم إلى كل النقاط على بعد مترين، وهكذا. لذلك أول مرة تصل فيها الموجة إلى نقطة هي أقصر مسافة إليها.

🕳️ البحث بالعمق (DFS): تخيّل مستكشفًا في كهف. يأخذ أول ممر ويمشي فيه إلى آخره. عندما يصل إلى نهاية مسدودة، يرجع إلى آخر مفترق ويجرب الممر التالي. هذا هو التراجع من الدرس 5 بالضبط.

🏦 من عالم المدفوعات: الحسابات هي العقد، والتحويلات هي الحواف. إذا خرج المال من حساب ثم رجع إليه بعد عدة تحويلات، فهذه حلقة، وقد تكون علامة على غسيل أموال.

BFS و DFS: نفس الكود تقريبًا، والفرق في هيكل البيانات

BFS: طابور deque

أول من دخل أول من يخرج. يزور العقد طبقة بعد طبقة حسب المسافة. يجد أقصر طريق في رسم غير موزون.

DFS: مكدس أو عودية

آخر من دخل أول من يخرج. يذهب في العمق أولًا. مناسب للمكونات، والحلقات، والترتيب الطوبولوجي، وكل المسارات.

المشترك: seen

كلاهما يحفظ العقد التي زارها، حتى لا يدور في حلقة إلى الأبد، ولا يزور العقدة مرتين.

لماذا التعقيد O(V + E)؟

كل عقدة تدخل الطابور أو المكدس مرة واحدة، فهذا O(V). وعند زيارة كل عقدة نمرّ على جيرانها. مجموع الجيران لكل العقد في رسم غير موجّه هو:

$$\sum_{v \in V} \deg(v) = 2E \;\Rightarrow\; O(V) + O(2E) = O(V + E)$$

كل حافة تُرى مرتين، مرة من كل طرف. وهذا هو أفضل ما يمكن، لأنك يجب أن ترى الرسم كله مرة واحدة على الأقل.

أي خوارزمية تختار؟

اكتشاف الحلقة في رسم موجّه: ثلاثة ألوان

في الرسم الموجّه لا يكفي أن نعرف "هل زرنا العقدة؟". نحتاج أن نعرف هل هي في المسار الحالي؟ لذلك نستخدم ثلاثة ألوان:

أمثلة الكود

مثال 1: بناء قائمة الجوار وأقصر طريق بـ BFS

from collections import defaultdict, deque

Graph = dict[str, list[str]]


def build_graph(edges: list[tuple[str, str]]) -> Graph:
    """Undirected adjacency list. Time: O(V + E)."""
    graph: defaultdict[str, list[str]] = defaultdict(list)
    for a, b in edges:
        graph[a].append(b)
        graph[b].append(a)          # undirected: both directions
    return dict(graph)              # plain dict: reads won't create keys


def shortest_path(graph: Graph, start: str, goal: str) -> list[str] | None:
    """Fewest edges from start to goal. Time: O(V + E), Space: O(V)."""
    parent: dict[str, str | None] = {start: None}   # doubles as 'seen'
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal:
            path: list[str] = []
            while node is not None:                  # walk back to start
                path.append(node)
                node = parent[node]
            return path[::-1]
        for nxt in graph.get(node, []):
            if nxt not in parent:                    # mark when ENQUEUED
                parent[nxt] = node
                queue.append(nxt)
    return None


edges = [("A", "B"), ("A", "C"), ("B", "D"), ("C", "E"), ("D", "F"), ("E", "F")]
graph = build_graph(edges)
print(graph)
print(shortest_path(graph, "A", "F"))
print(shortest_path(graph, "A", "Z"))
{'A': ['B', 'C'], 'B': ['A', 'D'], 'C': ['A', 'E'], 'D': ['B', 'F'], 'E': ['C', 'F'], 'F': ['D', 'E']} ['A', 'B', 'D', 'F'] None

الشرح سطرًا بسطر

  1. defaultdict(list): نبني القوائم بدون فحص المفتاح (الدرس 4). ثم نحوّله إلى dict عادي، حتى لا تُنشئ القراءة مفاتيح جديدة بالخطأ.
  2. graph[b].append(a): الرسم غير موجّه، فنضيف الحافة في الاتجاهين. في الرسم الموجّه نحذف هذا السطر.
  3. parent: قاموس واحد يعمل كـ seen، ويحفظ من أين جئنا لكل عقدة، فنعيد بناء المسار في النهاية. هذه نفس فكرة parent في الدرس 7.
  4. deque.popleft(): O(1). لا تستخدم list.pop(0) (الخطأ 1 في الدرس 2).
  5. graph.get(node, []): العقدة "Z" غير موجودة، فلا يحدث KeyError.

مثال 2: ترتيب الزيارة في BFS و DFS

from collections import deque

graph = {
    "A": ["B", "C"], "B": ["A", "D"], "C": ["A", "E"],
    "D": ["B", "F"], "E": ["C", "F"], "F": ["D", "E"],
}


def bfs_order(graph: dict[str, list[str]], start: str) -> list[str]:
    seen = {start}
    order: list[str] = []
    queue = deque([start])
    while queue:
        node = queue.popleft()               # FIFO: oldest first
        order.append(node)
        for nxt in graph.get(node, []):
            if nxt not in seen:
                seen.add(nxt)
                queue.append(nxt)
    return order


def dfs_order(graph: dict[str, list[str]], start: str) -> list[str]:
    seen: set[str] = set()
    order: list[str] = []

    def visit(node: str) -> None:            # recursion = implicit stack
        seen.add(node)
        order.append(node)
        for nxt in graph.get(node, []):
            if nxt not in seen:
                visit(nxt)                   # go deep before trying siblings

    visit(start)
    return order


print(bfs_order(graph, "A"))
print(dfs_order(graph, "A"))
['A', 'B', 'C', 'D', 'E', 'F'] ['A', 'B', 'D', 'F', 'E', 'C']

الشرح سطرًا بسطر

  1. BFS يزور A، ثم الطبقة 1 (B و C)، ثم الطبقة 2 (D و E)، ثم F.
  2. DFS يذهب من A إلى B، ثم D، ثم F، ثم E، ثم C. يصل إلى C في النهاية رغم أنها جارة A مباشرة.
  3. لهذا السبب DFS لا يعطي أقصر طريق (انظر الخطأ 1).
  4. العودية في dfs_order تحتاج إطارًا لكل مستوى. مع سلسلة من 100,000 عقدة يظهر RecursionError (الدرس 5). استخدم مكدسًا يدويًا كما في المثال التالي.

مثال 3: عدّ المكونات المتصلة بمكدس يدوي

def count_components(n: int, edges: list[tuple[int, int]]) -> int:
    """Nodes are 0..n-1. Time: O(V + E), Space: O(V + E)."""
    graph: list[list[int]] = [[] for _ in range(n)]
    for a, b in edges:
        graph[a].append(b)
        graph[b].append(a)

    seen = [False] * n
    components = 0
    for start in range(n):
        if seen[start]:
            continue
        components += 1                  # a new, unexplored group
        seen[start] = True
        stack = [start]                  # explicit stack: no recursion limit
        while stack:
            node = stack.pop()
            for nxt in graph[node]:
                if not seen[nxt]:
                    seen[nxt] = True
                    stack.append(nxt)
    return components


print(count_components(5, [(0, 1), (1, 2), (3, 4)]))
print(count_components(4, []))
2 4

الشرح سطرًا بسطر

  1. عندما تكون العقد أرقامًا من 0 إلى n − 1، تكون القائمة أسرع وأخف من القاموس (الدرس 4).
  2. for start in range(n): نجرب كل عقدة كبداية. إذا لم نزرها من قبل، فهي بداية مكوّن جديد.
  3. stack.pop(): نأخذ من النهاية، فنذهب في العمق. لو استبدلت المكدس بـ deque و popleft، يصبح الكود BFS، وتبقى النتيجة نفسها.
  4. count_components(4, []): بدون حواف، كل عقدة مكوّن مستقل.

مثال 4: اكتشاف حلقة تحويلات في رسم موجّه

WHITE, GRAY, BLACK = 0, 1, 2


def find_cycle(graph: dict[str, list[str]]) -> list[str] | None:
    """Return one directed cycle as a path, or None. Time: O(V + E)."""
    color: dict[str, int] = {}
    path: list[str] = []

    def visit(node: str) -> list[str] | None:
        color[node] = GRAY                       # on the current path
        path.append(node)
        for nxt in graph.get(node, []):
            state = color.get(nxt, WHITE)
            if state == GRAY:                    # back edge -> cycle
                return path[path.index(nxt):] + [nxt]
            if state == WHITE:
                found = visit(nxt)
                if found:
                    return found
        path.pop()
        color[node] = BLACK                      # fully explored, safe
        return None

    for node in list(graph):
        if color.get(node, WHITE) == WHITE:
            found = visit(node)
            if found:
                return found
    return None


transfers = {"A": ["B"], "B": ["C"], "C": ["A", "D"], "D": []}
diamond = {"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}
print(find_cycle(transfers))
print(find_cycle(diamond))
['A', 'B', 'C', 'A'] None

الشرح سطرًا بسطر

  1. GRAY: العقدة في المسار الحالي. إذا وصلنا إليها من جديد، فقد رجعنا إلى الخلف، وهذه حلقة.
  2. path[path.index(nxt):]: الحلقة هي جزء المسار من أول ظهور لـ nxt حتى الآن.
  3. BLACK: انتهينا من العقدة وكل ما بعدها، ولم نجد حلقة. إذا وصلنا إليها من فرع آخر، فهذا ليس حلقة.
  4. في diamond نصل إلى D مرتين (من B ومن C)، لكنها سوداء في المرة الثانية، لذلك النتيجة None. سترى في الخطأ 2 ماذا يحدث لو استخدمت seen فقط.

الأخطاء الشائعة

خطأ 1: استخدام DFS لأقصر طريق

الرسم: A—B و B—C و C—D و A—D. أقصر طريق من A إلى D هو خطوة واحدة.

❌ الطريقة الخاطئة

def path_dfs(graph, start, goal):
    seen = {start}
    path = [start]
    def visit(node):
        if node == goal:
            return True
        for nxt in graph.get(node, []):
            if nxt not in seen:
                seen.add(nxt)
                path.append(nxt)
                if visit(nxt):
                    return True
                path.pop()
        return False
    return path if visit(start) else None

g = build_graph([("A","B"), ("B","C"),
                 ("C","D"), ("A","D")])
print(path_dfs(g, "A", "D"))
# ['A', 'B', 'C', 'D']  not shortest!

خطأ 2: اكتشاف الحلقة في رسم موجّه بـ seen فقط

❌ الطريقة الخاطئة

def has_cycle(graph):
    seen = set()
    def visit(node):
        if node in seen:
            return True          # "seen before" != cycle
        seen.add(node)
        return any(visit(n) for n in graph.get(node, []))
    return any(visit(n) for n in list(graph)
               if n not in seen)

diamond = {"A": ["B", "C"], "B": ["D"],
           "C": ["D"], "D": []}
print(has_cycle(diamond))  # True  wrong!

✅ الطريقة الصحيحة

def has_cycle(graph):
    on_path, done = set(), set()
    def visit(node):
        if node in on_path:
            return True          # back to current path
        if node in done:
            return False         # finished elsewhere
        on_path.add(node)
        found = any(visit(n) for n in graph.get(node, []))
        on_path.remove(node)
        done.add(node)
        return found
    return any(visit(n) for n in list(graph))

print(has_cycle(diamond))  # False
⚠️ لماذا الأولى خاطئة؟ نصل إلى D من B، ثم نصل إليها من C. الكود الأول يقول "رأيتها من قبل، إذن توجد حلقة". لكن لا يوجد طريق يرجع من D إلى A. الحلقة تعني الرجوع إلى عقدة في المسار الحالي (رمادية)، وليس إلى أي عقدة زرناها. الكود الصحيح يستخدم مجموعتين بدل الألوان الثلاثة، والفكرة واحدة. ملاحظة: في الرسم غير الموجّه القاعدة مختلفة، وتتجاهل فيها الحافة التي جئت منها (parent).

أخطاء أخرى متكررة

  • نسيان seen: في أي رسم فيه حلقة، يدور البحث إلى الأبد، أو يظهر RecursionError.
  • وضع العقدة في seen عند الإخراج في BFS: النتيجة صحيحة، لكن نفس العقدة قد تدخل الطابور مرات كثيرة. في رسم كثيف يصبح الطابور ضخمًا جدًا. ضعها في seen عند الإضافة.
  • نسيان الاتجاه الثاني: في الرسم غير الموجّه، إذا أضفت graph[a].append(b) فقط، فلن تصل من b إلى a.
  • القراءة من defaultdict أثناء البحث: graph[node] لعقدة غير موجودة يضيفها إلى الرسم، ويغيّر حجمه أثناء المرور عليه. استخدم .get(node, []).
  • نسيان العقد بلا حواف: إذا بنيت العقد من الحواف فقط، فالعقدة المعزولة لا تظهر. ابنِ العقد من قائمة كاملة.
  • BFS على رسم موزون: BFS يعدّ الخطوات، ولا يجمع التكاليف. مع الرسوم استخدم Dijkstra (تمرين 4).

أفضل الممارسات

  • ارسم الرسم أولًا لمثال صغير. حدد: ما العقد؟ ما الحواف؟ هل هي موجّهة؟ هل هي موزونة؟
  • ابدأ بقائمة الجوار إلا إذا كان عندك سبب قوي لغيرها.
  • اختر BFS لأقصر طريق، واختر DFS للمكونات والحلقات والترتيب.
  • استخدم مكدسًا يدويًا عندما قد يكون العمق كبيرًا (أكثر من بضعة آلاف).
  • اجعل seen هو نفسه parent أو dist، فتوفّر هيكلًا كاملًا.
  • في الشبكات اكتب قائمة الاتجاهات مرة واحدة: ((1,0), (-1,0), (0,1), (0,-1))، وتحقق من الحدود قبل القراءة.
  • اختبر: رسمًا فارغًا، وعقدة واحدة، وعقدًا معزولة، وحلقة ذاتية A → A، وأكثر من مكوّن.
💡 إشارات في نص المسألة: "أقل عدد خطوات" و "أقرب" و "أقصر طريق" تشير إلى BFS. و "مرتبطة" و "مجموعات" و "جزر" تشير إلى المكونات. و "يعتمد على" و "قبل" و "ترتيب التنفيذ" تشير إلى الترتيب الطوبولوجي. و "أرخص" و "أقل تكلفة" مع أوزان تشير إلى Dijkstra.

مشروع تطبيقي صغير: كشف شبكات الاحتيال

القصة: المحتالون يفتحون حسابات كثيرة بأسماء مختلفة، لكنهم غالبًا يستخدمون نفس الأجهزة أو نفس أرقام الهواتف. إذا اشترك حسابان في جهاز أو رقم، فهما مرتبطان. والارتباط ينتقل: إذا كان ACC1 مرتبطًا بـ ACC2، و ACC2 مرتبطًا بـ ACC3، فالثلاثة في نفس الشبكة، حتى لو لم يشترك ACC1 و ACC3 في أي شيء مباشرة. المطلوب: كل شبكة فيها 3 حسابات أو أكثر.

طبّق الخطوات الست

  1. الفهم: المدخلات أزواج (account, identifier)، والمعرّف جهاز أو رقم هاتف. المخرجات قوائم الحسابات في كل شبكة كبيرة.
  2. الحالات الطرفية: حساب وحده، وجهاز يستخدمه 1000 حساب، وحساب بأكثر من معرّف.
  3. الحل البدائي: قارن كل زوج حسابات، وكرر حتى لا يتغير شيء. هذا O(n²) أو أسوأ.
  4. التحسين: جمّع الحسابات حسب المعرّف (نمط التجميع من الدرس 4)، ثم ابنِ رسمًا، ثم جد المكونات المتصلة بـ BFS.
  5. الكود: بالأسفل.
  6. الاختبار: سلسلة من 4 حسابات، وزوج صغير، وحساب وحده.
from collections import defaultdict, deque

Link = tuple[str, str]  # (account_id, identifier) e.g. a device or a phone


def fraud_rings(links: list[Link], min_size: int = 3) -> list[list[str]]:
    """Accounts sharing any identifier (directly or through a chain) form a ring.
    Time: O(V + L) where L = len(links), Space: O(V + L)."""
    # 1) group accounts by identifier (Lesson 4: grouping pattern)
    by_identifier: defaultdict[str, list[str]] = defaultdict(list)
    for account, ident in links:
        by_identifier[ident].append(account)

    # 2) connect accounts that share an identifier
    graph: defaultdict[str, set[str]] = defaultdict(set)
    for accounts in by_identifier.values():
        hub = accounts[0]
        for other in accounts[1:]:           # star, not all pairs: O(k) edges, not O(k^2)
            graph[hub].add(other)
            graph[other].add(hub)

    # 3) connected components with BFS
    seen: set[str] = set()
    rings: list[list[str]] = []
    for start in sorted({a for a, _ in links}):   # every account, even isolated ones
        if start in seen:
            continue
        seen.add(start)
        component: list[str] = []
        queue = deque([start])
        while queue:
            node = queue.popleft()
            component.append(node)
            for nxt in graph.get(node, ()):          # .get: don't create keys
                if nxt not in seen:
                    seen.add(nxt)
                    queue.append(nxt)
        if len(component) >= min_size:
            rings.append(sorted(component))
    return rings


links: list[Link] = [
    ("ACC1", "device:D1"), ("ACC2", "device:D1"),    # ACC1 - ACC2
    ("ACC2", "phone:010"), ("ACC3", "phone:010"),    # ACC2 - ACC3
    ("ACC3", "device:D7"), ("ACC4", "device:D7"),    # ACC3 - ACC4
    ("ACC5", "device:D2"), ("ACC6", "device:D2"),    # a small pair
    ("ACC7", "device:D9"),                            # alone
]

print(fraud_rings(links))
print(fraud_rings(links, min_size=2))
[['ACC1', 'ACC2', 'ACC3', 'ACC4']] [['ACC1', 'ACC2', 'ACC3', 'ACC4'], ['ACC5', 'ACC6']]

الشرح

  1. التجميع أولًا: by_identifier يحوّل "من يستخدم هذا الجهاز؟" إلى بحث O(1).
  2. الحواف على شكل نجمة: إذا استخدم 1000 حساب نفس الجهاز، فربط كل زوج يعطي حوالي 500 ألف حافة. ربط كل حساب بالحساب الأول (hub) يعطي 999 حافة فقط، والمكونات تبقى نفسها. هذا تحسين حقيقي يوفّر الذاكرة.
  3. set للجيران: إذا اشترك حسابان في جهاز ورقم معًا، لا تتكرر الحافة.
  4. الربط غير المباشر: ACC1 و ACC4 لا يشتركان في أي شيء، لكن BFS وجد السلسلة ACC1 → ACC2 → ACC3 → ACC4. هذا ما لا تكشفه المقارنة المباشرة.
  5. sorted(...): ترتيب ثابت للنتيجة، حتى يكون التقرير والاختبارات قابلة للتكرار.
💡 في الأنظمة الحقيقية: الحسابات والأجهزة تصل باستمرار، فإعادة البحث كله مع كل حساب جديد مكلفة. هنا تُستخدم Union-Find (Disjoint Set Union)، التي تدمج المجموعات مع كل رابط جديد بتكلفة شبه ثابتة. ولاكتشاف حلقات التحويل (round-tripping)، طبّق find_cycle من المثال 4 على رسم التحويلات الموجّه. والنظامان معًا يعطيان صورة قوية للمخاطر.

اختبر نفسك

1. أي خوارزمية تجد أقل عدد خطوات بين حسابين في رسم غير موزون؟
2. ما تعقيد BFS مع قائمة الجوار؟
3. في BFS، لماذا نضع العقدة في seen عند إضافتها إلى الطابور وليس عند إخراجها؟
4. في DFS على رسم موجّه، وصلنا إلى عقدة لونها رمادي. ماذا يعني ذلك؟
5. لكل تحويل رسوم مختلفة (غير سالبة). كيف تجد أرخص طريق؟

تمرين 1 (سهل): عدد الجزر

اكتب دالة num_islands(grid: list[str]) -> int. كل "1" أرض، وكل "0" ماء. الجزيرة أرض متصلة أفقيًا أو عموديًا.

💡 تلميح

الشبكة رسم ضمني: كل خانة أرض عقدة، وجيرانها الأربعة حوافها. عدّ المكونات كما في المثال 3. احفظ الخانات المزورة كـ tuple في set.

✅ الحل 
def num_islands(grid: list[str]) -> int:
    # Time: O(R*C), Space: O(R*C)
    if not grid:
        return 0
    rows, cols = len(grid), len(grid[0])
    seen: set[tuple[int, int]] = set()
    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] != "1" or (r, c) in seen:
                continue
            count += 1
            seen.add((r, c))
            stack = [(r, c)]
            while stack:
                x, y = stack.pop()
                for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    nx, ny = x + dx, y + dy
                    if (0 <= nx < rows and 0 <= ny < cols
                            and grid[nx][ny] == "1" and (nx, ny) not in seen):
                        seen.add((nx, ny))
                        stack.append((nx, ny))
    return count


print(num_islands(["11000", "11000", "00100", "00011"]))
print(num_islands(["111", "010", "111"]))
print(num_islands([]))
3 1 0

تحقق من الحدود قبل القراءة من grid. في Python، الموقع السالب مثل grid[-1] لا يرفع خطأ، بل يقرأ آخر صف، فيعطي نتيجة خاطئة بدون أي رسالة.

تمرين 2 (متوسط): ترتيب تشغيل الخدمات

اكتب دالة build_order(services: list[str], deps: list[tuple[str, str]]) -> list[str] | None. كل زوج (before, after) يعني أن before يجب أن يعمل قبل after. أرجع ترتيبًا صحيحًا، أو None إذا كانت هناك اعتمادية دائرية.

💡 تلميح

خوارزمية Kahn: احسب درجة الدخول لكل خدمة. ضع في الطابور كل خدمة درجتها 0، أي لا تعتمد على أي شيء. عندما تخرج خدمة، أنقص درجة كل خدمة تعتمد عليها. إذا بقيت خدمات لم تخرج، فهناك حلقة.

✅ الحل 
from collections import deque


def build_order(services: list[str], deps: list[tuple[str, str]]) -> list[str] | None:
    # Kahn's algorithm. Time: O(V + E), Space: O(V + E)
    graph: dict[str, list[str]] = {s: [] for s in services}
    indegree: dict[str, int] = {s: 0 for s in services}
    for before, after in deps:
        graph[before].append(after)
        indegree[after] += 1

    queue = deque(s for s in services if indegree[s] == 0)
    order: list[str] = []
    while queue:
        s = queue.popleft()
        order.append(s)
        for nxt in graph[s]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:       # all its dependencies are done
                queue.append(nxt)
    return order if len(order) == len(services) else None


services = ["api", "db", "auth", "payments"]
deps = [("db", "auth"), ("db", "payments"), ("auth", "api"), ("payments", "api")]
print(build_order(services, deps))
print(build_order(["a", "b"], [("a", "b"), ("b", "a")]))
['db', 'auth', 'payments', 'api'] None

الخدمات داخل الحلقة لا تصل درجتها إلى 0 أبدًا، فلا تدخل الطابور. لذلك يكفي فحص len(order) == len(services) لاكتشاف الحلقة. هذه طريقة ثانية لاكتشاف الحلقات، ولا تحتاج عودية.

تمرين 3 (متوسط): المسافة إلى أقرب منفذ دفع

عندك خريطة: "O" منفذ دفع، و "." شارع، و "#" مبنى لا يمكن عبوره. اكتب دالة nearest_outlet(grid: list[str]) -> list[list[int]] ترجع لكل خانة عدد الخطوات إلى أقرب منفذ، و -1 للمباني والخانات التي لا يمكن الوصول إليها.

💡 تلميح

لا تشغّل BFS من كل خانة، فهذا O((R·C)²). شغّل BFS واحدًا من كل المنافذ معًا (multi-source BFS): ضعها كلها في الطابور بمسافة 0 في البداية. استخدم جدول المسافات نفسه كـ seen.

✅ الحل 
from collections import deque


def nearest_outlet(grid: list[str]) -> list[list[int]]:
    # Multi-source BFS. Time: O(R*C), Space: O(R*C)
    rows, cols = len(grid), len(grid[0])
    dist = [[-1] * cols for _ in range(rows)]      # -1 doubles as "not seen"
    queue: deque[tuple[int, int]] = deque()
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "O":
                dist[r][c] = 0
                queue.append((r, c))               # all sources start together

    while queue:
        r, c = queue.popleft()
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if (0 <= nr < rows and 0 <= nc < cols
                    and grid[nr][nc] != "#" and dist[nr][nc] == -1):
                dist[nr][nc] = dist[r][c] + 1
                queue.append((nr, nc))
    return dist


city = [
    "O..#",
    "...#",
    "#..O",
]
for row in nearest_outlet(city):
    print(row)
[0, 1, 2, -1] [1, 2, 2, -1] [-1, 2, 1, 0]

لماذا يعمل؟ كأن هناك عقدة وهمية متصلة بكل المنافذ، ونحن نبدأ منها. الموجات من كل المنافذ تتقدم معًا، فأول موجة تصل إلى خانة هي من أقرب منفذ. لاحظ [[-1] * cols for _ in range(rows)] وليس الضرب (الدرس 7).

تمرين 4 (صعب): أرخص طريق تحويل (Dijkstra)

لكل تحويل بين جهتين رسوم بالقروش. اكتب دالة cheapest_route(graph, start, goal) ترجع (أقل تكلفة، المسار)، أو None. الرسوم غير سالبة.

💡 تلميح

مثل BFS، لكن استبدل الطابور بـ heapq، وأخرج دائمًا العقدة ذات أقل تكلفة حتى الآن. عندما تجد طريقًا أرخص إلى جار، حدّث تكلفته وأضفه إلى الـ heap. وتجاهل العناصر القديمة التي تكلفتها أكبر من أفضل تكلفة معروفة.

✅ الحل 
import heapq

Weighted = dict[str, list[tuple[str, int]]]   # node -> [(neighbor, fee_cents)]


def cheapest_route(graph: Weighted, start: str, goal: str) -> tuple[int, list[str]] | None:
    # Dijkstra. Time: O((V + E) log V), Space: O(V)
    best: dict[str, int] = {start: 0}
    parent: dict[str, str | None] = {start: None}
    heap: list[tuple[int, str]] = [(0, start)]
    while heap:
        cost, node = heapq.heappop(heap)          # cheapest known node
        if node == goal:
            path: list[str] = []
            cur: str | None = node
            while cur is not None:
                path.append(cur)
                cur = parent[cur]
            return cost, path[::-1]
        if cost > best[node]:
            continue                              # stale entry: a cheaper one was processed
        for nxt, fee in graph.get(node, []):
            new_cost = cost + fee
            if nxt not in best or new_cost < best[nxt]:
                best[nxt] = new_cost
                parent[nxt] = node
                heapq.heappush(heap, (new_cost, nxt))
    return None


routes: Weighted = {
    "Wallet": [("Bank_A", 500), ("Bank_B", 100)],
    "Bank_B": [("Bank_A", 150), ("Merchant", 900)],
    "Bank_A": [("Merchant", 200)],
}

print(cheapest_route(routes, "Wallet", "Merchant"))
print(cheapest_route(routes, "Merchant", "Wallet"))
(450, ['Wallet', 'Bank_B', 'Bank_A', 'Merchant']) None

BFS كان سيختار Wallet → Bank_A → Merchant، لأنه خطوتان فقط، لكن تكلفته 700. أما Dijkstra فوجد طريقًا من 3 خطوات بتكلفة 450. لماذا يجب أن تكون الرسوم غير سالبة؟ لأن الخوارزمية تفترض أن العقدة التي تخرج من الـ heap لن تصبح أرخص بعد ذلك. ومع حافة سالبة ينهار هذا الافتراض، وهذه نفس فكرة الرتابة في الدرسين 3 و 6.

الخلاصة

  • الرسم البياني = عقد وحواف. اسأل دائمًا: هل هو موجّه؟ هل هو موزون؟
  • قائمة الجوار هي التمثيل الافتراضي، وذاكرتها O(V + E).
  • BFS يستخدم deque، ويزور طبقة بعد طبقة، ويجد أقصر طريق بعدد الخطوات.
  • DFS يستخدم العودية أو مكدسًا، ويذهب في العمق. مناسب للمكونات والحلقات والترتيب.
  • كلاهما O(V + E)، وكلاهما يحتاج seen. في BFS ضع العقدة فيه عند الإضافة إلى الطابور.
  • الحلقة في الرسم الموجّه = الوصول إلى عقدة رمادية، أي عقدة في المسار الحالي، وليس أي عقدة زرناها.
  • الترتيب الطوبولوجي (Kahn) يرتب الاعتماديات، ويكتشف الحلقات في نفس الوقت.
  • BFS من عدة مصادر يحسب المسافة إلى أقرب مصدر في مرور واحد.
  • مع الأوزان غير السالبة استخدم Dijkstra مع heapq.
  • الشبكات رسوم ضمنية، فاحسب الجيران عند الحاجة وتحقق من الحدود.
