مقدمة

📝 تذكير: في الدرس 1 قلنا إن حل Two Sum بالقاموس أسرع من الحل البدائي. قلنا إن الأول O(n) والثاني O(n²). في هذا الدرس ستفهم معنى هذه الرموز، وتتعلم كيف تحسبها بنفسك.

لماذا لا نقيس السرعة بالثواني فقط؟ لأن الثواني تختلف من جهاز إلى جهاز، ومن لغة إلى لغة. أما Big-O فيجيب عن سؤال أهم: إذا زاد حجم المدخلات، كيف يزيد الوقت؟

الكود الذي يعالج 100 معاملة في ثانية واحدة قد يحتاج ساعات لمعالجة مليون معاملة. وقد يحتاج ثانيتين فقط. الفرق بين الحالتين هو التعقيد، وليس سرعة الجهاز.

في هذا الدرس ستتعلم قواعد حساب التعقيد، والتكلفة المخفية لعمليات Python الشائعة، وكيف تحلل الكود الذي فيه عودية (recursion).

تشبيه من الحياة

🎉 تخيّل أنك تريد أن تدعو n شخصًا إلى حفلة:

• O(1): تكتب رسالة واحدة في مجموعة الواتساب. الوقت ثابت، سواء كانوا 10 أشخاص أو 1000.
• O(log n): تخبر شخصين، وكل واحد منهما يخبر شخصين، وهكذا. عدد الجولات صغير جدًا. مع 1000 شخص تحتاج حوالي 10 جولات فقط.
• O(n): تتصل بكل شخص وحده. إذا تضاعف العدد، تضاعف الوقت.
• O(n²): تطلب من كل شخص أن يصافح كل الأشخاص الآخرين. إذا تضاعف العدد، صار الوقت أربعة أضعاف.

Big-O لا يهتم بالوقت الذي تأخذه المكالمة الواحدة. هو يهتم بكيفية نمو الوقت كله عندما يزيد عدد الأشخاص.

المفاهيم الأساسية

التعريف ببساطة

نقول إن الدالة f(n) هي O(g(n)) إذا وُجد ثابت c، وكانت f(n) بعد حجم معيّن لا تتجاوز c · g(n):

$$f(n) = O(g(n)) \iff \exists\, c > 0,\ n_0 : \ f(n) \le c \cdot g(n) \quad \forall\, n \ge n_0$$

لا تقلق من الرموز. الفكرة باختصار: عندما يكبر n، نهتم بشكل النمو فقط، ونتجاهل الثوابت والتفاصيل الصغيرة.

القواعد الخمس لحساب التعقيد

1. احذف الثوابت

O(2n) هي O(n)، و O(500) هي O(1).

2. احذف الحدود الصغيرة

O(n² + n) هي O(n²)، لأن n² يسيطر عندما يكبر n.

3. المتتالي يُجمع

حلقة بعد حلقة: O(n) + O(n) = O(n).

4. المتداخل يُضرب

حلقة داخل حلقة: O(n) × O(n) = O(n²).

5. مدخلات مختلفة = متغيرات مختلفة

قائمتان بحجمين a و b: النتيجة O(a + b) أو O(a × b)، وليست O(n).

مثال على القاعدتين 1 و 2:

$$3n^2 + 5n + 2 \;\Rightarrow\; O(n^2)$$

لماذا؟ عندما يكون n = 1000، يساوي الحد 3n² ثلاثة ملايين، بينما يساوي 5n خمسة آلاف فقط. الحد الصغير لا يغيّر الصورة.

من أين يأتي log n؟

عندما تقسم المسألة على 2 في كل خطوة، تسأل: بعد كم خطوة نصل إلى عنصر واحد؟

$$\frac{n}{2^k} = 1 \;\Rightarrow\; 2^k = n \;\Rightarrow\; k = \log_2 n$$

مع مليون عنصر، يكفي حوالي 20 خطوة. لهذا يُعدّ O(log n) سريعًا جدًا، وهو أساس Binary Search في الدرس 6.

تحليل دالة سطرًا بسطر

هذه دالة تتحقق من وجود زوج مجموعه target باستخدام الترتيب ومؤشرين. سنحسب تكلفة كل سطر، ثم نجمع النتائج.

الخطوة 1: الترتيب

nums_sorted = sorted(nums)O(n log n)
left, right = 0, len(nums_sorted) - 1
while left < right:
total = nums_sorted[left] + nums_sorted[right]
...move left or right...
return False

دالة sorted() في Python تأخذ O(n log n). وهي أيضًا تنشئ قائمة جديدة، فتحتاج ذاكرة O(n).

الخطوة 2: الإسناد

nums_sorted = sorted(nums)O(n log n)
left, right = 0, len(nums_sorted) - 1O(1)
while left < right:
total = nums_sorted[left] + nums_sorted[right]
...move left or right...
return False

الدالة len() في Python ثابتة O(1)، لأن القائمة تحفظ طولها.

الخطوة 3: الحلقة

nums_sorted = sorted(nums)O(n log n)
left, right = 0, len(nums_sorted) - 1O(1)
while left < right:≤ n times
total = nums_sorted[left] + nums_sorted[right]O(1)
...move left or right...O(1)
return False

في كل دورة يتحرك مؤشر واحد خطوة نحو الآخر. لذلك تتكرر الحلقة n مرة على الأكثر. تكلفة الحلقة: n × O(1) = O(n).

الخطوة 4: اجمع واحذف الحدود الصغيرة ✅

nums_sorted = sorted(nums)O(n log n) ← dominant
left, right = 0, len(nums_sorted) - 1O(1)
while left < right: ...O(n)
return FalseO(1)

المجموع: O(n log n) + O(1) + O(n). الحد المسيطر هو n log n، لذلك الوقت O(n log n) والذاكرة O(n). لاحظ أن الترتيب أبطأ من الحلقة نفسها. هذا هو عنق الزجاجة.

التكلفة المُطفأة: لماذا append سريع؟

القائمة في Python تحجز مساحة أكبر من حاجتها. عندما تمتلئ، تنشئ مساحة أكبر بنسبة ثابتة (حوالي 1.125 مرة في CPython)، ثم تنسخ العناصر إليها. هذا النسخ يأخذ O(n)، لكنه نادر. لنبسّط الحساب ونفترض أن المساحة تتضاعف. عندها يكون مجموع عمليات النسخ لـ n إضافة:

$$1 + 2 + 4 + \dots + n \;<\; 2n \;\Rightarrow\; \frac{2n}{n} = O(1) \text{ per append}$$

نفس الفكرة تبقى صحيحة مع أي نسبة نمو ثابتة. لذلك نقول إن append تأخذ O(1) مُطفأة (amortized). بعض الإضافات بطيئة، لكن المتوسط ثابت.

أمثلة الكود

مثال 1: عدّ العمليات بدل قياس الثواني

الثواني تختلف من جهاز إلى آخر، أما عدد العمليات فلا يتغير. سنعدّ الخطوات في ثلاث دوال.

def steps_linear(n: int) -> int:
    count = 0
    for _ in range(n):
        count += 1
    return count


def steps_quadratic(n: int) -> int:
    count = 0
    for _ in range(n):
        for _ in range(n):
            count += 1
    return count


def steps_log(n: int) -> int:
    count = 0
    while n > 1:
        n //= 2        # halve the problem each step
        count += 1
    return count


for n in [16, 1024]:
    print(n, steps_linear(n), steps_quadratic(n), steps_log(n))
16 16 256 4 1024 1024 1048576 10

الشرح سطرًا بسطر

  1. steps_linear: حلقة واحدة تتكرر n مرة، فالتعقيد O(n).
  2. steps_quadratic: حلقة داخل حلقة، n × n، فالتعقيد O(n²).
  3. n //= 2: نقسم على 2 في كل دورة، فالتعقيد O(log n).
  4. لاحظ النتيجة: عندما زاد n حوالي 64 مرة (من 16 إلى 1024)، زادت الخطوات الخطية 64 مرة، والتربيعية حوالي 4096 مرة، واللوغاريتمية من 4 إلى 10 فقط.

مثال 2: التكلفة المخفية في in

الكلمة in تبدو بسيطة، لكن تكلفتها تختلف حسب نوع البيانات. هذه دالة تجد العناصر المشتركة بين قائمتين:

def common_slow(a: list[int], b: list[int]) -> list[int]:
    # 'x in b' scans the whole list b -> O(len(b)) each time
    return [x for x in a if x in b]          # O(a * b)


def common_fast(a: list[int], b: list[int]) -> list[int]:
    b_set = set(b)                            # O(b) once
    return [x for x in a if x in b_set]       # O(1) average lookup -> O(a)


a = [4, 9, 2, 7, 1]
b = [7, 3, 4, 8]
print(common_slow(a, b))
print(common_fast(a, b))
[4, 7] [4, 7]

الشرح سطرًا بسطر

  1. x in b عندما تكون b قائمة: Python يمرّ على العناصر واحدًا واحدًا، فالتكلفة O(b). نكرر هذا لكل عنصر في a، فيصبح المجموع O(a × b).
  2. set(b): ننشئ المجموعة مرة واحدة بتكلفة O(b).
  3. x in b_set: البحث في set يأخذ O(1) في المتوسط، كما رأينا في القاموس في الدرس 1.
  4. المجموع O(a + b). مع قائمتين فيهما 100,000 عنصر، ننتقل من 10 مليارات عملية إلى حوالي 200 ألف.
⚠️ انتبه: نفس السطر x in something قد يكون O(1) أو O(n). لا يكفي أن تنظر إلى الحلقات، بل اسأل أيضًا: ما تكلفة كل عملية داخل الحلقة؟

مثال 3: تحليل العودية (Fibonacci)

كيف تحلل دالة تستدعي نفسها؟ ارسم شجرة الاستدعاءات، ثم اضرب عدد العقد في العمل الذي تقوم به كل عقدة.

def fib_naive(n: int, counter: list[int]) -> int:
    counter[0] += 1                      # count every call
    if n < 2:
        return n
    return fib_naive(n - 1, counter) + fib_naive(n - 2, counter)


def fib_memo(n: int, memo: dict[int, int], counter: list[int]) -> int:
    counter[0] += 1
    if n in memo:
        return memo[n]                   # already computed: no new calls
    if n < 2:
        return n
    memo[n] = fib_memo(n - 1, memo, counter) + fib_memo(n - 2, memo, counter)
    return memo[n]


slow_calls = [0]
fast_calls = [0]
print(fib_naive(20, slow_calls), "calls:", slow_calls[0])
print(fib_memo(20, {}, fast_calls), "calls:", fast_calls[0])
6765 calls: 21891 6765 calls: 39

الشرح سطرًا بسطر

  1. counter: list[int]: نستخدم قائمة فيها عنصر واحد كعدّاد، لأن الدالة تستطيع تعديل محتوى القائمة.
  2. fib_naive: كل استدعاء يولّد استدعاءين، فعدد الاستدعاءات ينمو تقريبًا مثل 2ⁿ. الشجرة تحسب fib(18) مرتين، و fib(17) ثلاث مرات، وهكذا.
  3. fib_memo: نحفظ كل نتيجة في memo. كل قيمة من 2 إلى 20 تُحسب مرة واحدة فقط وتولّد استدعاءين، فالمجموع 1 + 2 × 19 = 39.
  4. الذاكرة: كلا الحلين يحتاج O(n) في مكدس الاستدعاءات، لأن أطول سلسلة هي 20 → 19 → … → 1. الحل الثاني يحتاج أيضًا O(n) للقاموس.
💡 قاعدة العودية: الوقت = (عدد الاستدعاءات) × (العمل في كل استدعاء). والذاكرة = (أعمق مسار في الشجرة) + (أي تخزين إضافي). هذا الحفظ (memoization) هو بداية البرمجة الديناميكية في الدرس 7.

الأخطاء الشائعة

خطأ 1: pop(0) داخل حلقة

❌ الطريقة الخاطئة: O(n²)

def process_queue(tasks: list[str]) -> list[str]:
    done = []
    while tasks:
        task = tasks.pop(0)   # shifts ALL items left: O(n)
        done.append(task.upper())
    return done

print(process_queue(["a", "b", "c"]))  # ['A', 'B', 'C']

✅ الطريقة الصحيحة: O(n)

from collections import deque

def process_queue(tasks: list[str]) -> list[str]:
    queue = deque(tasks)
    done = []
    while queue:
        task = queue.popleft()  # O(1)
        done.append(task.upper())
    return done

print(process_queue(["a", "b", "c"]))  # ['A', 'B', 'C']
⚠️ لماذا الأولى خاطئة؟ النتيجة صحيحة، لكن السرعة سيئة. عندما تحذف أول عنصر من القائمة، تتحرك كل العناصر الباقية خطوة إلى اليسار. هذا يأخذ O(n) في كل دورة، فيصبح المجموع O(n²). أما deque فمصممة للحذف من الطرفين في O(1).

خطأ 2: الظن أن كل حلقتين تعطيان O(n²)

❌ تحليل خاطئ

def min_and_max(nums: list[int]) -> tuple[int, int]:
    lo = nums[0]
    for x in nums:        # loop 1
        lo = min(lo, x)
    hi = nums[0]
    for x in nums:        # loop 2
        hi = max(hi, x)
    return lo, hi

# "Two loops, so O(n²)"  ← wrong analysis

✅ تحليل صحيح

def min_and_max(nums: list[int]) -> tuple[int, int]:
    lo = nums[0]
    for x in nums:        # O(n)
        lo = min(lo, x)
    hi = nums[0]
    for x in nums:        # + O(n)
        hi = max(hi, x)
    return lo, hi

# O(n) + O(n) = O(2n) = O(n)  ← sequential, not nested
⚠️ لماذا الأولى خاطئة؟ الحلقتان متتاليتان وليستا متداخلتين. المتتالي يُجمع، والمتداخل يُضرب (القاعدتان 3 و 4).

أخطاء أخرى متكررة

  • نسيان تكلفة الدوال الجاهزة: sorted() تأخذ O(n log n)، والتقطيع nums[a:b] يأخذ O(b − a) لأنه ينسخ العناصر، و list.index() و list.count() تأخذان O(n).
  • استخدام n لقائمتين مختلفتين: اكتب O(a + b) وليس O(n).
  • نسيان ذاكرة العودية: عودية بعمق n تحتاج O(n) ذاكرة، حتى لو لم تنشئ أي قائمة. وفي Python الحد الافتراضي للعمق حوالي 1000.
  • الخلط بين المتوسط والأسوأ: البحث في dict يأخذ O(1) في المتوسط. في الأسوأ، مع تصادمات كثيرة، قد يصل إلى O(n). لكن هذا نادر جدًا عمليًا.

أفضل الممارسات

  • اكتب التعقيد في تعليق فوق كل دالة مهمة، مثل # Time: O(n), Space: O(n).
  • حلّل الوقت والذاكرة معًا. المحاور في المقابلة سيسألك عن الاثنين.
  • اسأل عن كل سطر داخل الحلقة: هل هو O(1) فعلًا؟
  • اختر هيكل البيانات حسب العملية: البحث المتكرر يحتاج set أو dict، والطابور يحتاج deque، وأصغر عنصر يحتاج heapq.
  • قِس قبل أن تحسّن في المشاريع الحقيقية. استخدم timeit أو cProfile لتجد عنق الزجاجة الحقيقي.
  • تذكّر أن الثوابت مهمة مع المدخلات الصغيرة. حل O(n²) بسيط قد يكون أسرع من حل O(n log n) معقد عندما يكون n = 20.
💡 نصيحة للمقابلات: بعد أن تكتب الحل، قل التعقيد قبل أن يسألك المحاور. وقل أيضًا مصدره، مثل: "الترتيب هو عنق الزجاجة بتعقيد O(n log n)، والحلقة O(n)".

متى لا يكفي Big-O؟

  • الثوابت المخفية: حلّان بتعقيد O(n) قد يختلفان في السرعة 10 مرات.
  • الذاكرة المؤقتة (Cache): المرور على مصفوفة متصلة في الذاكرة أسرع من التنقل بين عُقد متفرقة، حتى لو كان التعقيد واحدًا.
  • الدوال المكتوبة بلغة C: دوال مثل sum() و sorted() في Python أسرع بكثير من حلقة تكتبها أنت بنفس التعقيد.
📝 الخلاصة العملية: استخدم Big-O لتختار الفكرة الصحيحة، ثم استخدم القياس لتختار التنفيذ الأسرع.

مشروع تطبيقي صغير: تحليل وتحسين تسوية المعاملات

القصة: كل يوم يصلك كشف من البنك فيه أرقام المعاملات، وعندك سجل المعاملات في نظامك. تريد أن تعرف شيئين: أي معاملات في البنك غير موجودة في نظامك؟ وأي معاملات في نظامك غير موجودة في البنك؟ قد يصل عدد المعاملات إلى مليون في اليوم.

الخطوة 1: الحل الأول، ثم حلّل تعقيده

def reconcile_slow(bank_ids: list[str], system_ids: list[str]) -> tuple[list[str], list[str]]:
    # Time: O(b * s)  -- 'in list' inside a loop, twice
    missing_in_system = [tx for tx in bank_ids if tx not in system_ids]
    missing_in_bank = [tx for tx in system_ids if tx not in bank_ids]
    return missing_in_system, missing_in_bank

مع مليون معاملة في كل قائمة، يحتاج هذا الحل حوالي 10¹² × 2 مقارنة. هذا يأخذ أيامًا في Python، وليس دقائق.

الخطوة 2: الحل المحسّن

def reconcile(bank_ids: list[str], system_ids: list[str]) -> tuple[list[str], list[str]]:
    """
    Time:  O(b + s + m log m)   m = number of mismatches (sorting the report)
    Space: O(b + s)             two sets
    """
    bank = set(bank_ids)        # O(b)
    system = set(system_ids)    # O(s)
    missing_in_system = sorted(bank - system)   # set difference: O(b), then sort
    missing_in_bank = sorted(system - bank)     # O(s), then sort
    return missing_in_system, missing_in_bank


bank_statement = ["TX1", "TX2", "TX3", "TX5"]
system_records = ["TX1", "TX3", "TX4"]

not_in_system, not_in_bank = reconcile(bank_statement, system_records)
print("In bank, missing in system:", not_in_system)
print("In system, missing in bank:", not_in_bank)
In bank, missing in system: ['TX2', 'TX5'] In system, missing in bank: ['TX4']

الشرح

  1. set(bank_ids): نحوّل القائمة إلى مجموعة مرة واحدة بتكلفة O(b).
  2. bank - system: الفرق بين مجموعتين يمرّ على عناصر bank ويبحث عن كل عنصر في system بتكلفة O(1)، فالمجموع O(b).
  3. sorted(...): الفرق بين المجموعات لا يحفظ أي ترتيب، فنرتب التقرير حتى يكون سهل القراءة. التكلفة O(m log m)، و m عادةً صغير لأن الفروقات قليلة.
  4. الموازنة: دفعنا ذاكرة O(b + s) لنوفّر وقتًا هائلًا. من حوالي 2 × 10¹² عملية إلى حوالي 4 × 10⁶.
⚠️ حالة طرفية: الـ set يحذف التكرار. إذا ظهرت نفس المعاملة مرتين في كشف البنك (خصم مكرر)، لن يكتشفها هذا الحل. لاكتشاف التكرار، استخدم Counter بدل set وقارن الأعداد. التعقيد يبقى O(b + s).

💡 تلميح

item not in result يمرّ على قائمة تكبر مع الوقت. أضف هيكلًا ثانيًا يجيب عن سؤال "هل رأيته؟" بسرعة، واترك القائمة لحفظ الترتيب.

✅ الحل 
def unique(items: list[str]) -> list[str]:
    # Time: O(n), Space: O(n)
    seen: set[str] = set()
    result: list[str] = []
    for item in items:
        if item not in seen:      # O(1) average
            seen.add(item)
            result.append(item)   # list keeps the original order
    return result


print(unique(["cash", "card", "wallet", "card", "cash"]))
['cash', 'card', 'wallet']

الحل الأصلي O(n²) في الأسوأ (عندما تكون كل العناصر مختلفة). الـ set للبحث السريع، والـ list للترتيب. يوجد حل أقصر هو list(dict.fromkeys(items))، لأن القاموس في Python يحفظ ترتيب الإضافة. تعقيده أيضًا O(n).

تمرين 4 (صعب): حلقة while داخل for، لكنها O(n)!

هذه الدالة ترجع طول أطول جزء متصل من النص لا يتكرر فيه أي حرف. يبدو تعقيدها O(n²). أثبت أنه O(n).

def longest_unique(s: str) -> int:
    seen: set[str] = set()
    left = 0
    best = 0
    for right, ch in enumerate(s):
        while ch in seen:
            seen.remove(s[left])
            left += 1
        seen.add(ch)
        best = max(best, right - left + 1)
    return best


print(longest_unique("abcabcbb"))
print(longest_unique("bbbbb"))
print(longest_unique("pwwkew"))
3 1 3
💡 تلميح

لا تعدّ تكرارات الحلقة الداخلية في كل دورة. اسأل بدلًا من ذلك: كم مرة يمكن أن يتحرك left في الدالة كلها؟

✅ الحل

المؤشر right يتحرك n مرة. المؤشر left يتحرك للأمام فقط ولا يرجع، ولا يتجاوز right. لذلك يتحرك n مرة على الأكثر في الدالة كلها، وليس في كل دورة.

مجموع كل الحركات: n + n = 2n، فالتعقيد O(n). هذا تحليل مُطفأ (amortized): بعض الدورات تعمل كثيرًا، لكن المجموع محدود.

الذاكرة: O(k)، حيث k عدد الحروف المختلفة. هذا هو نمط Sliding Window، وسنشرحه بالتفصيل في الدرس القادم.

الخلاصة

  • Big-O يقيس كيف ينمو الوقت أو الذاكرة مع حجم المدخلات، وليس عدد الثواني.
  • احذف الثوابت والحدود الصغيرة: 3n² + 5n → O(n²).
  • الحلقات المتتالية تُجمع، والمتداخلة تُضرب.
  • القسمة على 2 في كل خطوة تعطي O(log n).
  • استخدم متغيرًا مختلفًا لكل مدخل: O(a + b) وليس O(n).
  • انتبه للتكلفة المخفية: in list، و pop(0)، و sorted()، والتقطيع.
  • العودية: الوقت = عدد الاستدعاءات × العمل في كل استدعاء، والذاكرة تشمل عمق المكدس.
  • append تأخذ O(1) مُطفأة، والتحليل المُطفأ يشرح لماذا تكون بعض الحلقات المتداخلة O(n).
  • اختيار هيكل البيانات المناسب هو أسهل طريقة لتحسين التعقيد.
  • Big-O يساعدك على اختيار الفكرة، والقياس يساعدك على اختيار التنفيذ.
