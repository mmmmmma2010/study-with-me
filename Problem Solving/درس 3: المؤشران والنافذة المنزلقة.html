المؤشران والنافذة المنزلقة (Two Pointers & Sliding Window)

ستتعلم كيف تحوّل حلولًا بتعقيد O(n²) إلى O(n) عندما تحرّك مؤشرين بذكاء بدل تجربة كل الاحتمالات.

مقدمة

📝 تذكير: في تمرين 4 من الدرس 2 رأيت حلقة while داخل حلقة for، وكان تعقيدها O(n) وليس O(n²). السبب أن المؤشر left يتحرك للأمام فقط. هذه الفكرة هي أساس هذا الدرس كله.

الحل البدائي لكثير من المسائل يجرب كل زوج (i, j)، فيكون تعقيده O(n²). لكن في بعض المسائل نعرف مسبقًا أن أزواجًا كثيرة لا تفيد. عندها نستطيع أن نتخطاها كلها دفعة واحدة.

طريقة المؤشرين (Two Pointers) تستخدم موقعين في القائمة يتحركان حسب قاعدة واضحة. والنافذة المنزلقة (Sliding Window) نوع خاص منها، وفيها يحدّد المؤشران جزءًا متصلًا من القائمة.

في هذا الدرس ستتعلم ثلاثة أنواع من المؤشرين، ونوعين من النوافذ. وستتعلم أيضًا متى تعمل هذه الطريقة ومتى تفشل. في النهاية ستبني نظامًا يكشف المعاملات المشبوهة على بطاقة دفع.

تشبيه من الحياة

📚 المؤشران المتقابلان: تخيّل رفًّا عليه كتب مرتبة من الأخف إلى الأثقل، وتريد كتابين وزنهما معًا 10 كيلو بالضبط. تمسك أخف كتاب بيدك اليسرى وأثقل كتاب بيدك اليمنى. إذا كان المجموع ثقيلًا جدًا، تبدّل الكتاب الذي في اليمنى بكتاب أخف منه. وإذا كان خفيفًا جدًا، تبدّل الكتاب الذي في اليسرى بكتاب أثقل. لن تحتاج أن تجرب كل زوج من الكتب.

🚆 النافذة المنزلقة: تخيّل أنك تنظر من نافذة قطار. ترى دائمًا جزءًا متصلًا من الطريق. عندما يتحرك القطار، يدخل منظر جديد من جهة ويخرج منظر قديم من الجهة الأخرى. أنت لا تنظر إلى الطريق كله من جديد في كل لحظة، بل تتابع ما دخل وما خرج فقط.

المفاهيم الأساسية

الأنواع الأربعة

1. المؤشران المتقابلان

left = 0 و right = n - 1، ثم يقتربان. يُستخدم مع القوائم المرتبة، والمسائل التي تبحث عن زوج، والنصوص المتناظرة (palindrome).

2. القارئ والكاتب

كلاهما يتحرك للأمام. يُستخدم لحذف عناصر أو تصفيتها داخل القائمة نفسها.

3. النافذة الثابتة

طولها k. أضف العنصر الذي دخل، واطرح العنصر الذي خرج.

4. النافذة المتغيرة

وسّع من اليمين دائمًا. صغّر من اليسار ما دام الشرط مكسورًا (أو ما دام محققًا، حسب المسألة).

لماذا يعمل المؤشران المتقابلان؟

لنعد إلى مسألة Two Sum، لكن مع قائمة مرتبة. لنفترض أن nums[left] + nums[right] < target.

الآن خذ أي عنصر nums[j] حيث j ≤ right. القائمة مرتبة، لذلك nums[j] ≤ nums[right]. إذن:

$$nums[left] + nums[j] \;\le\; nums[left] + nums[right] \;<\; target$$

معنى هذا أن nums[left] لا يكوّن زوجًا صحيحًا مع أي عنصر باقٍ. لذلك نحذفه بأمان، أي نكتب left += 1. نفس المنطق يعمل في الاتجاه الآخر: إذا كان المجموع أكبر من target، نحذف nums[right].

💡 الفكرة الأساسية: كل مقارنة تحذف عنصرًا كاملًا مع كل أزواجه. لذلك نحتاج n مقارنة على الأكثر بدل n²/2.

لماذا تعمل النافذة المنزلقة؟ (شرط الرتابة)

لنفترض أن كل الأرقام موجبة، وأنك تبحث عن أقصر جزء متصل مجموعه أكبر من أو يساوي target:

  • عندما توسّع النافذة من اليمين، يزيد المجموع دائمًا.
  • عندما تصغّرها من اليسار، يقل المجموع دائمًا.

لذلك عندما يصبح المجموع كافيًا، تعرف أن التوسيع لن يعطيك نافذة أقصر. ولهذا تصغّر النافذة فورًا. لو وُجدت أرقام سالبة، فقد يزيد المجموع بعد التصغير، وعندها تنهار هذه القاعدة.

⚠️ قبل أن تستخدم النافذة المنزلقة اسأل: هل التوسيع يغيّر الشرط في اتجاه واحد دائمًا؟ إذا كان الجواب لا (كما مع الأرقام السالبة)، استخدم Prefix Sum مع dict، كما في تمرين 4 من الدرس 1.

لماذا النافذة المتغيرة O(n) رغم الحلقة الداخلية؟

هذا هو التحليل المُطفأ من الدرس 2. المؤشر right يتحرك n مرة. المؤشر left يتحرك للأمام فقط، ولا يتجاوز right. إذن:

$$\underbrace{n}_{\text{right moves}} + \underbrace{n}_{\text{left moves (total)}} = 2n = O(n)$$

كل عنصر يدخل النافذة مرة واحدة، ويخرج منها مرة واحدة على الأكثر.

أمثلة الكود

مثال 1: المؤشران المتقابلان (Two Sum على قائمة مرتبة)

def two_sum_sorted(nums: list[int], target: int) -> tuple[int, int] | None:
    """nums must be sorted ascending. Time: O(n), Space: O(1)."""
    left, right = 0, len(nums) - 1
    while left < right:                 # strict: never pair an element with itself
        total = nums[left] + nums[right]
        if total == target:
            return (left, right)
        if total < target:
            left += 1                    # need a bigger sum
        else:
            right -= 1                   # need a smaller sum
    return None


print(two_sum_sorted([1, 3, 4, 6, 8, 11], 10))
print(two_sum_sorted([1, 2, 3], 100))
(2, 3) None

الشرح سطرًا بسطر

  1. left, right = 0, len(nums) - 1: نبدأ من الطرفين.
  2. while left < right: نتوقف عندما يلتقي المؤشران. علامة < هنا وليست <=، لأننا لا نريد أن نجمع العنصر مع نفسه.
  3. إذا كان المجموع صغيرًا، نحرك left نحو أرقام أكبر.
  4. إذا كان المجموع كبيرًا، نحرك right نحو أرقام أصغر.
  5. المقارنة مع الدرس 1: حل dict كان يحتاج ذاكرة O(n). هذا الحل يحتاج O(1)، لكنه يعمل فقط عندما تكون القائمة مرتبة مسبقًا.

مثال 2: القارئ والكاتب (حذف التكرار في المكان)

المطلوب: احذف التكرار من قائمة مرتبة بدون إنشاء قائمة جديدة، وأرجع عدد العناصر الفريدة.

def remove_duplicates(nums: list[int]) -> int:
    """nums is sorted. Keeps unique values at the front. Time: O(n), Space: O(1)."""
    if not nums:
        return 0
    write = 1                              # nums[:write] holds unique values
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:  # a new value
            nums[write] = nums[read]
            write += 1
    return write


data = [1, 1, 2, 3, 3, 3, 5]
k = remove_duplicates(data)
print(k, data[:k])
4 [1, 2, 3, 5]

الشرح سطرًا بسطر

  1. if not nums: حالة طرفية، قائمة فارغة.
  2. write = 1: أول عنصر فريد دائمًا. الثابت: كل ما قبل write قيم فريدة ومرتبة.
  3. read يمرّ على كل عنصر مرة واحدة.
  4. nums[read] != nums[write - 1]: نقارن مع آخر قيمة فريدة كتبناها. القائمة مرتبة، لذلك يظهر أي تكرار بجانب أصله.
  5. القيم بعد write لا تهمنا، لذلك نطبع data[:k] فقط.

مثال 3: النافذة الثابتة

def max_window_sum(nums: list[int], k: int) -> int | None:
    """Largest sum of k consecutive items. Time: O(n), Space: O(1)."""
    if k <= 0 or k > len(nums):
        return None
    window = sum(nums[:k])               # first window: O(k)
    best = window
    for right in range(k, len(nums)):
        window += nums[right] - nums[right - k]   # add new, remove old
        best = max(best, window)
    return best


print(max_window_sum([2, 1, 5, 1, 3, 2], 3))
print(max_window_sum([4, 2], 3))
9 None

الشرح سطرًا بسطر

  1. k > len(nums): لا توجد نافذة بهذا الطول.
  2. sum(nums[:k]): مجموع النافذة الأولى.
  3. nums[right - k]: العنصر الذي خرج من النافذة. عندما يدخل العنصر right، يخرج العنصر الذي يبعد عنه k خطوات.
  4. هذه النافذة تعمل حتى مع الأرقام السالبة، لأن طولها ثابت ولا نحتاج شرط الرتابة.

مثال 4: النافذة المتغيرة (أقصر جزء مجموعه ≥ target)

def min_window_len(nums: list[int], target: int) -> int:
    """nums are POSITIVE. Shortest subarray with sum >= target, or 0.
    Time: O(n), Space: O(1)."""
    left = 0
    window_sum = 0
    best = len(nums) + 1                 # "infinity" that stays an int
    for right, num in enumerate(nums):
        window_sum += num                # 1) expand
        while window_sum >= target:      # 2) shrink while still valid
            best = min(best, right - left + 1)
            window_sum -= nums[left]
            left += 1
    return 0 if best > len(nums) else best


print(min_window_len([2, 3, 1, 2, 4, 3], 7))
print(min_window_len([1, 4, 4], 4))
print(min_window_len([1, 1, 1], 10))
2 1 0

الشرح سطرًا بسطر

  1. best = len(nums) + 1: قيمة أكبر من أي طول ممكن. إذا بقيت كما هي، فلا يوجد جواب.
  2. التوسيع: نضيف العنصر الجديد دائمًا.
  3. التصغير: ما دامت النافذة صالحة، نسجل طولها ثم نحاول أن نجعلها أقصر. استخدمنا while وليس if، لأن النافذة قد تحتاج أكثر من خطوة تصغير.
  4. right - left + 1: طول النافذة. النافذة [left, right] تشمل الطرفين.
  5. في المثال الأول، الجواب هو [4, 3] بطول 2.

الأخطاء الشائعة

خطأ 1: النافذة المنزلقة مع أرقام سالبة

المطلوب: عدد الأجزاء المتصلة التي مجموعها k. الجواب الصحيح لـ [1, -1, 0] و k = 0 هو 3: [1, -1]، و [0]، و [1, -1, 0].

❌ الطريقة الخاطئة

def count_sum_k(nums: list[int], k: int) -> int:
    left = 0
    window = 0
    count = 0
    for right, num in enumerate(nums):
        window += num
        while window > k and left <= right:
            window -= nums[left]
            left += 1
        if window == k:
            count += 1
    return count

print(count_sum_k([1, -1, 0], 0))  # 1  wrong!

✅ الطريقة الصحيحة

def count_sum_k(nums: list[int], k: int) -> int:
    count = 0
    prefix = 0
    seen: dict[int, int] = {0: 1}
    for num in nums:
        prefix += num
        count += seen.get(prefix - k, 0)
        seen[prefix] = seen.get(prefix, 0) + 1
    return count

print(count_sum_k([1, -1, 0], 0))  # 3
⚠️ لماذا الأولى خاطئة؟ مع الأرقام السالبة، توسيع النافذة قد يُنقص المجموع، وتصغيرها قد يزيده. لذلك لا تعرف أي مؤشر يجب أن تحرك. في الخطوة الأولى حذفت النافذة العدد 1، ففقدت الجزء [1, -1] إلى الأبد. الحل الصحيح هو Prefix Sum من الدرس 1، وتعقيده أيضًا O(n).

خطأ 2: <= بدل < في المؤشرين المتقابلين

❌ الطريقة الخاطئة

def two_sum_sorted(nums: list[int], target: int):
    left, right = 0, len(nums) - 1
    while left <= right:          # allows left == right
        total = nums[left] + nums[right]
        if total == target:
            return (left, right)
        if total < target:
            left += 1
        else:
            right -= 1
    return None

print(two_sum_sorted([5], 10))  # (0, 0)  wrong!

✅ الطريقة الصحيحة

def two_sum_sorted(nums: list[int], target: int):
    left, right = 0, len(nums) - 1
    while left < right:           # two DIFFERENT positions
        total = nums[left] + nums[right]
        if total == target:
            return (left, right)
        if total < target:
            left += 1
        else:
            right -= 1
    return None

print(two_sum_sorted([5], 10))  # None
⚠️ لماذا الأولى خاطئة؟ عندما يكون left == right، يشير المؤشران إلى نفس العنصر، فيجمع الكود 5 مع نفسه. هذا نفس الخطأ الذي رأيته في الدرس 1، لكن في شكل مختلف.

أخطاء أخرى متكررة

  • if بدل while في التصغير: قد تحتاج النافذة أن تصغر عدة خطوات مرة واحدة. مع if تبقى النافذة غير صالحة.
  • خطأ في طول النافذة: الطول هو right - left + 1، وليس right - left.
  • تحديث الجواب في المكان الخطأ: في مسائل "الأطول"، حدّث الجواب بعد التصغير. وفي مسائل "الأقصر"، حدّثه داخل حلقة التصغير.
  • الترتيب عندما تحتاج المواقع الأصلية: الترتيب يغيّر المواقع (راجع الخطأ 2 في الدرس 1).
  • نسيان حذف المفتاح من القاموس: إذا وصل العدّ إلى صفر ولم تحذف المفتاح، فإن len(counts) يعطيك رقمًا خاطئًا.

  • اكتب الثابت في تعليق، مثل # nums[:write] holds unique values. هذا السطر يساعدك على كتابة الكود، ويثبت صحته.
  • تحقق من شرط الرتابة قبل أن تكتب أي نافذة متغيرة. اسأل: هل هناك أرقام سالبة؟
  • استخدم أسماء واضحة مثل left/right و read/write و window_sum، وليس i/j.
  • اختبر الحالات الطرفية: قائمة فارغة، وعنصر واحد، وكل العناصر متساوية، و k أكبر من طول القائمة.
  • احتفظ بالحل البدائي لاختبار الضغط، كما تعلمت في الدرس 1. أخطاء المؤشرين غالبًا أخطاء صغيرة بفرق واحد (off-by-one)، والاختبار العشوائي يكشفها بسرعة.
  • اشرح سبب تحريك كل مؤشر. إذا لم تستطع أن تقول "لماذا هذا العنصر لا يفيد بعد الآن؟"، فقد يكون الحل خاطئًا.
💡 إشارات في نص المسألة: كلمات مثل "مرتبة" و "زوج" و "متناظر" تشير إلى المؤشرين المتقابلين. وكلمات مثل "جزء متصل" و "أطول" و "أقصر" و "خلال k" تشير إلى النافذة. وعبارة "في المكان بدون ذاكرة إضافية" تشير إلى القارئ والكاتب.

مشروع تطبيقي صغير: كشف المعاملات المشبوهة (Velocity Check)

القصة: أنظمة الحماية من الاحتيال تراقب سرعة استخدام البطاقة. إذا استُخدمت نفس البطاقة أكثر من limit مرة خلال 60 ثانية، نطلق تنبيهًا. المطلوب: لكل بطاقة، جد أول نافذة زمنية مشبوهة.

طبّق الخطوات الست

  1. الفهم: المدخلات قائمة (card_id, timestamp) بالثواني، وغير مرتبة. المخرجات قاموس فيه البطاقات المشبوهة، ولكل بطاقة (بداية النافذة، نهايتها، العدد).
  2. الحالات الطرفية: بطاقة لها معاملة واحدة، ومعاملات في نفس الثانية، ونافذة تنتهي بالضبط عند 60 ثانية.
  3. الحل البدائي: لكل معاملة، عدّ المعاملات التي في الـ 60 ثانية قبلها. التعقيد O(n²).
  4. التحسين: بعد الترتيب، الشرط رتيب: كلما تقدم الوقت، تخرج المعاملات القديمة ولا تعود. هذه نافذة متغيرة على الزمن.
  5. الكود: بالأسفل.
  6. الاختبار: بطاقة مشبوهة، وبطاقة عادية.
from collections import defaultdict

Alert = tuple[int, int, int]  # (window_start, window_end, count)


def velocity_alert(times: list[int], window_seconds: int, limit: int) -> Alert | None:
    """times sorted ascending, window_seconds > 0.
    Finds the first window [t - window_seconds, t] with more than `limit` transactions.
    Time: O(n), Space: O(1)."""
    left = 0
    for right, ts in enumerate(times):
        while ts - times[left] >= window_seconds:   # drop transactions that are too old
            left += 1
        count = right - left + 1
        if count > limit:
            return (times[left], ts, count)
    return None


def scan_cards(transactions: list[tuple[str, int]], window_seconds: int, limit: int) -> dict[str, Alert]:
    """Time: O(n log n) because of sorting, Space: O(n)."""
    by_card: dict[str, list[int]] = defaultdict(list)
    for card, ts in transactions:
        by_card[card].append(ts)

    alerts: dict[str, Alert] = {}
    for card, times in by_card.items():
        times.sort()
        alert = velocity_alert(times, window_seconds, limit)
        if alert:
            alerts[card] = alert
    return alerts


transactions = [
    ("C1", 0), ("C2", 5), ("C1", 15), ("C1", 70), ("C2", 200),
    ("C1", 80), ("C1", 95), ("C1", 110), ("C2", 210),
]

print(scan_cards(transactions, window_seconds=60, limit=3))
print(scan_cards(transactions, window_seconds=60, limit=4))
{'C1': (70, 110, 4)} {}

الشرح

  1. defaultdict(list): نجمع أوقات كل بطاقة في قائمة. لن تحتاج أن تتحقق هل المفتاح موجود أم لا. سنشرح هذا بالتفصيل في الدرس 4.
  2. times.sort(): النافذة تحتاج ترتيبًا زمنيًا. هذا هو عنق الزجاجة بتعقيد O(n log n).
  3. ts - times[left] >= window_seconds: المعاملة التي عند left أقدم من 60 ثانية، فنخرجها. لن تعود أبدًا، لأن الوقت يتقدم فقط. هذه هي الرتابة.
  4. left لا يتجاوز right أبدًا، لأن ts - times[right] = 0، وهذا أصغر من window_seconds.
  5. البطاقة C1 لها 4 معاملات بين الثانية 70 والثانية 110، وهذا أكثر من الحد (3).
💡 في الأنظمة الحقيقية: المعاملات تصل كتدفق مستمر (stream) ومرتبة زمنيًا تقريبًا. لذلك تحفظ لكل بطاقة deque فيها أوقات آخر 60 ثانية. عند وصول معاملة جديدة، تحذف الأوقات القديمة من البداية بـ popleft(). هذه نفس النافذة المنزلقة، وتكلفة كل معاملة O(1) مُطفأة.

اختبر نفسك

1. في المؤشرين المتقابلين على قائمة مرتبة، المجموع أصغر من target. ماذا تفعل؟
2. لماذا تفشل النافذة المتغيرة غالبًا مع الأرقام السالبة؟
3. نافذة متغيرة فيها حلقة while داخل حلقة for. ما التعقيد؟
4. ما طول النافذة [left, right]؟
5. ما الذاكرة الإضافية لحذف التكرار من قائمة مرتبة بطريقة القارئ والكاتب؟

تمرين 1 (سهل): هل النص متناظر؟

اكتب دالة is_palindrome(s: str) -> bool. تجاهل المسافات والرموز، ولا تفرّق بين الحروف الكبيرة والصغيرة. مثلًا "A man, a plan, a canal: Panama" متناظر. لا تنشئ نصًا جديدًا.

💡 تلميح

مؤشران متقابلان. إذا كان الحرف عند أحد المؤشرين ليس حرفًا أو رقمًا، حرّك هذا المؤشر فقط. استخدم str.isalnum().

✅ الحل 
def is_palindrome(s: str) -> bool:
    # Time: O(n), Space: O(1)
    left, right = 0, len(s) - 1
    while left < right:
        if not s[left].isalnum():
            left += 1
        elif not s[right].isalnum():
            right -= 1
        elif s[left].lower() != s[right].lower():
            return False
        else:
            left += 1
            right -= 1
    return True


print(is_palindrome("A man, a plan, a canal: Panama"))
print(is_palindrome("paymob"))
print(is_palindrome(""))
True False True

الحل الأسهل هو cleaned == cleaned[::-1]. تعقيده أيضًا O(n)، لكنه يحتاج ذاكرة O(n) لإنشاء نصين جديدين.

تمرين 2 (متوسط): انقل الأصفار إلى النهاية

اكتب دالة move_zeros(nums: list[int]) -> None. تنقل كل الأصفار إلى نهاية القائمة، وتحافظ على ترتيب باقي العناصر. عدّل القائمة في مكانها.

💡 تلميح

القارئ والكاتب. كل عنصر غير صفري يذهب إلى موقع write. استخدم التبديل (swap) بدل النسخ، حتى تنتقل الأصفار تلقائيًا إلى الخلف.

✅ الحل 
def move_zeros(nums: list[int]) -> None:
    # Invariant: nums[:write] = non-zeros in original order
    # Time: O(n), Space: O(1)
    write = 0
    for read in range(len(nums)):
        if nums[read] != 0:
            nums[write], nums[read] = nums[read], nums[write]
            write += 1


data = [0, 1, 0, 3, 12]
move_zeros(data)
print(data)
[1, 3, 12, 0, 0]

الدالة ترجع None لأنها تعدّل القائمة نفسها، وهذا هو العرف في Python، مثل list.sort().

تمرين 3 (متوسط): 3Sum

اكتب دالة three_sum(nums: list[int]) -> list[list[int]]. ترجع كل الثلاثيات الفريدة التي مجموعها صفر. مثلًا [-1, 0, 1, 2, -1, -4] يعطي [[-1, -1, 2], [-1, 0, 1]].

💡 تلميح

رتّب القائمة. ثبّت العنصر الأول nums[i]، ثم ابحث عن زوج مجموعه -nums[i] بالمؤشرين المتقابلين. لتجنب التكرار، تخطَّ القيم المتساوية المتجاورة.

✅ الحل 
def three_sum(nums: list[int]) -> list[list[int]]:
    # Time: O(n^2), Space: O(n) for the sorted copy
    nums = sorted(nums)
    n = len(nums)
    result: list[list[int]] = []
    for i in range(n - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                         # skip duplicate first values
        left, right = i + 1, n - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                result.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1                # skip duplicate second values
    return result


print(three_sum([-1, 0, 1, 2, -1, -4]))
print(three_sum([0, 0, 0, 0]))
[[-1, -1, 2], [-1, 0, 1]] [[0, 0, 0]]

الحل البدائي O(n³). هنا نكرر حلًا بتعقيد O(n) لكل قيمة من n قيمة، فيصبح المجموع O(n²). استخدمنا sorted() وليس nums.sort()، حتى لا نغيّر قائمة المستخدم.

تمرين 4 (صعب): أطول جزء فيه k حروف مختلفة على الأكثر

اكتب دالة longest_k_distinct(s: str, k: int) -> int. مثلًا "eceba" و k = 2 يعطي 3، لأن الجزء هو "ece".

💡 تلميح

نافذة متغيرة. لا يكفي set هنا، لأن الحرف قد يتكرر داخل النافذة. استخدم قاموسًا يعدّ كل حرف. النافذة غير صالحة عندما يكون len(counts) > k. وعندما يصل عدّ حرف إلى صفر، احذف مفتاحه.

✅ الحل 
def longest_k_distinct(s: str, k: int) -> int:
    # Time: O(n), Space: O(k)
    counts: dict[str, int] = {}
    left = 0
    best = 0
    for right, ch in enumerate(s):
        counts[ch] = counts.get(ch, 0) + 1          # expand
        while len(counts) > k:                       # invalid: too many kinds
            out = s[left]
            counts[out] -= 1
            if counts[out] == 0:
                del counts[out]                      # keep len(counts) correct
            left += 1
        best = max(best, right - left + 1)           # "longest": update after shrinking
    return best


print(longest_k_distinct("eceba", 2))
print(longest_k_distinct("aa", 1))
print(longest_k_distinct("abc", 0))
3 2 0

الشرط رتيب: إضافة حرف لا تُنقص عدد الأنواع المختلفة، وحذف حرف لا يزيده. لذلك تعمل النافذة. لاحظ أننا نحدّث best بعد التصغير، لأننا نبحث عن الأطول. هذا الحل يجمع بين النافذة والعدّ بالقاموس، وهو موضوع الدرس القادم.

الخلاصة

  • طريقة المؤشرين تحذف احتمالات كثيرة في كل خطوة، فتحوّل O(n²) إلى O(n) غالبًا.
  • المؤشران المتقابلان: للقوائم المرتبة ومسائل الأزواج والنصوص المتناظرة.
  • القارئ والكاتب: للتعديل في المكان بذاكرة O(1).
  • النافذة الثابتة: أضف العنصر الذي دخل، واطرح العنصر الذي خرج.
  • النافذة المتغيرة: وسّع من اليمين دائمًا، وصغّر من اليسار بـ while.
  • النافذة المتغيرة تحتاج شرط الرتابة. مع الأرقام السالبة استخدم Prefix Sum مع dict.
  • التعقيد O(n) رغم الحلقة الداخلية، لأن كل مؤشر يتحرك n مرة على الأكثر في الدالة كلها.
  • طول النافذة right - left + 1، واستخدم < وليس <= عندما تحتاج عنصرين مختلفين.
  • اكتب الثابت في تعليق، فهو يرشدك إلى الكود الصحيح.
